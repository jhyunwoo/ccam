एखादे खाते वापर मर्यादेला (याला अनेकदा rate limit म्हणतात) पोहोचले की तुमच्याकडे दोन पर्याय असतात: मर्यादा रीसेट होईपर्यंत वाट पाहा, किंवा तेच संभाषण आत्ताच तुमच्या दुसऱ्या खात्यावर पुढे चालू ठेवा. ccam सोबत दुसरा पर्याय म्हणजे एकच कमांड: `ccam next --auto --continue`.

## Claude Code च्या कोणत्या मर्यादा आहेत?

Pro आणि Max प्लॅनवर Claude Code ला [5 तासांची सत्र मर्यादा आणि एक साप्ताहिक मर्यादा](https://support.claude.com/en/articles/11145838-using-claude-code-with-your-pro-or-max-plan) असते. दोन्ही वेब आणि ॲप्समधील Claude सोबत शेअर होतात, आणि वापर दोन्हींमधून एकाच वेळी मोजला जातो. एखादी मर्यादा संपली की Claude Code "You've hit your session limit · resets 3:45pm" असा [संदेश दाखवते](https://code.claude.com/docs/en/errors#youve-hit-your-session-limit). मॉडेल बदलून उपयोग होत नाही, कारण मर्यादा सर्व मॉडेल्सना लागू होतात.

## पर्याय 1: रीसेटची वाट पाहा

तुमच्याकडे एकच खाते असेल तर वाट पाहा. Claude Code च्या अलीकडच्या आवृत्त्या [उघड्या सत्रातच वाट पाहतात](https://code.claude.com/docs/en/interactive-mode#wait-for-a-usage-limit-to-reset) आणि मर्यादा रीसेट झाल्यावर काम आपोआप पुढे चालू ठेवतात. Claude Code मध्ये `/usage` तुमच्या प्लॅनच्या मर्यादांपैकी किती वापरले ते दाखवते.

## पर्याय 2: आत्ताच दुसऱ्या खात्यावर पुढे चालू ठेवा

तुमच्याकडे दुसरे खाते असेल, तर तुम्ही तेच संभाषण लगेच पुढे चालू ठेवू शकता. एकदा सेट करा:

```sh
curl -fsSL https://ccam.dev/install.sh | sh
ccam add personal
ccam add work
ccam group set default --add history
ccam statusline install
```

आता काम करताना स्टेटस लाइन खाते आणि त्याचा 5 तासांचा वापर दाखवते, त्यामुळे मर्यादा अचानक येत नाही.

मर्यादा गाठली की Claude Code मधून बाहेर पडा (`/exit`), मग:

```sh
ccam usage
```

```console
 1 personal  just now
   5-hour   ████████████████████ 100%  resets in 22m
   Weekly   ██████████████░░░░░░  68%  resets in 1d 9h
 2 work      just now
   5-hour   ██░░░░░░░░░░░░░░░░░░   8%  resets in 4h 12m
   Weekly   ████░░░░░░░░░░░░░░░░  19%  resets in 5d 2h
→ Most headroom: work   (open it with ccam next --auto)
```

सर्वात जास्त जागा असलेल्या खात्यात संभाषण उघडा:

```sh
ccam next --auto --continue
```

Claude Code `work` म्हणून सुरू होते, सध्याच्या फोल्डरमधील सर्वात अलीकडील संभाषणासह, आतापर्यंत झालेल्या सगळ्या बोलण्यासह. इतिहास शेअर केल्याने (वरील `ccam group set default --add history`) दोन्ही खाती त्याच संभाषणावर काम करतात; त्याशिवाय Claude Code संभाषण `work` मध्ये कॉपी करते, आणि पहिल्या उत्तराला किती tokens पुन्हा वाचावे लागतील ते ccam सांगते.

Claude Code मध्ये [ccam plugin](/docs/install#claude-code-plugin) असेल, तर मर्यादेवर थांबलेले सत्र एक सूचना दाखवते आणि भरलेली window नोंदवते, त्यामुळे `ccam next --auto` ते खाते त्याच्या reset पूर्वी पुन्हा निवडत नाही. `/ccam:switch` (किंवा `/ccam:switch work`) `ccam next --continue` साठी संभाषणाची नोंद ठेवते, त्यामुळे नेमके तेच संभाषण पुढे चालू राहते.

**Team आणि Enterprise सीट्स.** आपोआप होणारी खाते निवड (`ccam next`, `--fallback`, `ccam pick`, डॅशबोर्डमधील `n` आणि, तुम्ही चालू केल्यावर, [`auto_switch`](/features/next#auto-switch)) एकाच Claude Team किंवा Enterprise organization मधील सीट्सदरम्यानही खाते बदलते, आणि यामुळे Anthropic च्या अटींचे उल्लंघन होऊ शकते. त्यावर अवलंबून राहण्यापूर्वी [FAQ](/docs/faq#am-i-allowed-to-use-several-claude-code-accounts) वाचा आणि तुमच्या संस्थेकडे आणि Anthropic कडे चौकशी करा.

## ccam आपोआप खाते बदलते का?

फक्त तुम्ही ते चालू केले तर.

- डीफॉल्टनुसार तुम्ही काम करत असताना ccam चालू नसते: ते Claude Code सुरू करते आणि स्वतःची जागा त्याला देते, त्यामुळे कधी बदलायचे ते तुम्ही ठरवता. `ccam next --auto` सर्वात कमी 5 तासांचा वापर असलेले खाते निवडते, 100% वर असलेली किंवा लॉगिन नसलेली खाती वगळते, आणि एकाच Team किंवा Enterprise organization मध्ये, किंवा वैयक्तिक प्लॅन्समध्येच राहते.
- `config.toml` मध्ये `relay = true` असेल, तर ccam त्याऐवजी सत्रासोबत चालू राहते, त्यामुळे `/ccam:switch` सत्राचे पर्याय, permission mode, effort level आणि agent कायम ठेवून संभाषण आपोआप पुढे चालू ठेवते; संभाषण दुसऱ्या organization च्या खात्यावर हलवण्यापूर्वी ccam तुम्हाला विचारते.
- `auto_switch = true` असेल (Linux आणि macOS; experimental), तर ccam हा बदलही स्वतः करते: Claude Code सत्र त्याच्या मर्यादेवर थांबवते आणि त्याच प्रकारच्या दुसऱ्या खात्यात जागा असते, तेव्हा ccam ते सत्र संपवते आणि संभाषण तिथे पुढे चालू ठेवते ([अटी आणि खर्च](/features/next#auto-switch)).

काही इतर टूल्स त्याऐवजी चालू सत्राचे लॉगिन बदलतात; [ccam आणि इतर account switchers](/compare/account-switchers) हा फरक समजावते.

## लक्षात ठेवण्यासारख्या गोष्टी

- `ccam next --continue` तुम्ही ज्या फोल्डरमध्ये काम करत होता त्याच फोल्डरमध्ये चालवा; संभाषणे प्रत्येक प्रोजेक्ट फोल्डरनुसार साठवली जातात.
- एकाच संभाषणावर एकाच वेळी दोन खाती चालवणे टाळा. तसा प्रयत्न केल्यास ccam सावध करते.
- इतिहास शेअर केलेला नसेल, तर संभाषण दुसऱ्या खात्यात कॉपी होते आणि दोन्ही प्रती आपापल्या वाटेने जातात; `/rewind` ज्या checkpoints मधून code परत आणते ते पहिल्या खात्याकडेच राहतात.
- नवीन खात्यावरील पहिला संदेश नेहमीपेक्षा जास्त मर्यादा वापरू शकतो, कारण त्या खात्याने अजून संभाषण cache केलेले नसते. `ccam next --continue --brief` त्याऐवजी ते एका छोट्या सारांशावर सुरू करते.
- अशा प्रकारे खाती बदलण्याची परवानगी आहे की नाही, हे प्रत्येक खात्याला लागू होणाऱ्या अटींवर अवलंबून आहे.

प्रत्येक पर्यायासाठी [वापर मर्यादा](/features/usage) आणि [पुढच्या खात्यावर जाणे](/features/next) पाहा.
