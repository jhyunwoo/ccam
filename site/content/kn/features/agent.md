Claude Code ನ ಸ್ವಂತ subagent ಗಳು ಅವುಗಳನ್ನು ಆರಂಭಿಸಿದ ಸೆಷನ್‌ನ ಖಾತೆಯಾಗಿ ರನ್ ಆಗುತ್ತವೆ, ಹೀಗಾಗಿ ಅವು ಆ ಖಾತೆಯ ಬಳಕೆಯನ್ನೇ ಖರ್ಚು ಮಾಡುತ್ತವೆ. `ccam agent "<task>"` ಅದೇ ಫೋಲ್ಡರ್‌ನಲ್ಲಿ `claude -p` ಮೂಲಕ ಒಂದು ಕಾರ್ಯವನ್ನು ನಿಮ್ಮ ಇನ್ನೊಂದು ಖಾತೆಯಾಗಿ ರನ್ ಮಾಡುತ್ತದೆ ಮತ್ತು Claude ನ ಕೊನೆಯ ಉತ್ತರವನ್ನು ಮುದ್ರಿಸುತ್ತದೆ. Claude Code ಸೆಷನ್‌ನಿಂದ ಕರೆದಾಗ, ಇದು ಇನ್ನೊಂದು ಖಾತೆಯ ಬಳಕೆಯನ್ನು ಖರ್ಚು ಮಾಡುವ subagent ನಂತೆ ಕೆಲಸ ಮಾಡುತ್ತದೆ, ಹೀಗಾಗಿ ಸೆಷನ್‌ನ ಸ್ವಂತ ಖಾತೆ ಖಾಲಿಯಾಗುತ್ತಿದ್ದ ನಂತರವೂ ಒಂದು ದೀರ್ಘ ಕಾರ್ಯ ಮುಂದುವರಿಯಬಹುದು.

**Team ಮತ್ತು Enterprise ಸೀಟುಗಳು.** `ccam agent` ಖಾತೆಯನ್ನು ತಾನೇ ಆಯ್ಕೆಮಾಡುತ್ತದೆ. ಒಂದೇ Claude Team ಅಥವಾ Enterprise ಸಂಸ್ಥೆಯೊಳಗೆ ಅದು ಕಾರ್ಯವನ್ನು ಇನ್ನೊಂದು ಸೀಟಿನಲ್ಲಿ ರನ್ ಮಾಡುತ್ತದೆ, ಇದು Anthropic ನ ನಿಯಮಗಳನ್ನು ಉಲ್ಲಂಘಿಸಬಹುದು. ಇದನ್ನು ಅವಲಂಬಿಸುವ ಮೊದಲು [ಪದೇ ಪದೇ ಕೇಳುವ ಪ್ರಶ್ನೆಗಳನ್ನು](/docs/faq#am-i-allowed-to-use-several-claude-code-accounts) ಓದಿ ಮತ್ತು ನಿಮ್ಮ ಸಂಸ್ಥೆ ಹಾಗೂ Anthropic ಬಳಿ ವಿಚಾರಿಸಿ.

## ಬಳಕೆ

Claude Code ಇದನ್ನು ತನ್ನ Bash ಟೂಲ್ ಮೂಲಕ ರನ್ ಮಾಡುತ್ತದೆ. [ccam ಪ್ಲಗಿನ್](/docs/install#claude-code-plugin) ಇನ್‌ಸ್ಟಾಲ್ ಆಗಿದ್ದರೆ, ಸರಳ ಮಾತುಗಳಲ್ಲಿ ಕೇಳಿ, ಉದಾಹರಣೆಗೆ "ಈ ಕಾರ್ಯದ ಭಾಗಗಳಿಗೆ ನನ್ನ ಇತರ ಖಾತೆಗಳನ್ನು ಬಳಸು", ಅಥವಾ ಅದನ್ನು ನಿಮ್ಮ CLAUDE.md ನಲ್ಲಿ ಬರೆಯಿರಿ. ಪ್ಲಗಿನ್‌ನ ಸ್ಕಿಲ್ Claude Code ಗೆ ಪ್ರತಿ ಏಜೆಂಟ್ ಅನ್ನು ಹಿನ್ನೆಲೆಯಲ್ಲಿ ಆರಂಭಿಸಲು, ತನ್ನಷ್ಟಕ್ಕೆ ತಾನೇ ಅರ್ಥವಾಗುವ ಕಾರ್ಯವನ್ನು ಬರೆಯಲು, ಮತ್ತು ಫೈಲ್‌ಗಳನ್ನು ಸಂಪಾದಿಸುವ ಏಜೆಂಟ್‌ಗಳಿಗೆ ಅವುಗಳದೇ ಆದ ಭಾಗ ಅಥವಾ git worktree ನೀಡಲು ಹೇಳುತ್ತದೆ.

```sh
ccam agent "find why TestParse fails and fix it; reply with what you changed"
ccam agent --model opus -- "-v breaks the parser: find out why"
ccam agent --json < task.md            # the task from standard input
ccam agent --resume 7f3c9a2e-… "now add a test for it"
ccam agent --wait=1h "…"               # nobody has room: wait for a reset
ccam --dry-run agent "…"               # the account and command it would run
```

```console
$ ccam agent "summarize what internal/usage does"
ccam: agent runs as work (12% of its 5 hours used); session 7f3c9a2e-5b1d-4c2a-9e8f-1a2b3c4d5e6f
internal/usage looks up the 5-hour and weekly usage of every account …
ccam: agent finished as work; follow up with: ccam agent --resume 7f3c9a2e-5b1d-4c2a-9e8f-1a2b3c4d5e6f "…"
```

Claude ನ ಕೊನೆಯ ಉತ್ತರ ಸ್ಟ್ಯಾಂಡರ್ಡ್ ಔಟ್‌ಪುಟ್‌ಗೆ ಹೋಗುತ್ತದೆ; `ccam:` ನಿಂದ ಆರಂಭವಾಗುವ ಸಾಲುಗಳು ಸ್ಟ್ಯಾಂಡರ್ಡ್ ಎರರ್‌ಗೆ ಹೋಗುತ್ತವೆ. `--json` ಬದಲಾಗಿ `{account, session_id, result, is_error, accounts}` ಅನ್ನು ಮುದ್ರಿಸುತ್ತದೆ, ಇಲ್ಲಿ `accounts` ಕಾರ್ಯವು ಯಾವ ಯಾವ ಖಾತೆಗಳಾಗಿ ರನ್ ಆಯಿತೋ ಅವೆಲ್ಲವನ್ನೂ ಪಟ್ಟಿ ಮಾಡುತ್ತದೆ.

ನಿರ್ಗಮನ ಕೋಡ್‌ಗಳು: claude ನ ಸ್ವಂತ ಕೋಡ್‌ಗಳು (ಏಜೆಂಟ್ ಮುಗಿದಾಗ `0`), ಕರೆದ ಖಾತೆಯನ್ನು ಬಿಟ್ಟು ಬೇರೆ ಯಾವ ಖಾತೆಯಲ್ಲೂ ಅವಕಾಶ ಇಲ್ಲದಿದ್ದಾಗ `75` (`EX_TEMPFAIL`), ಏಜೆಂಟ್ ಇನ್ನೊಂದು ಏಜೆಂಟ್ ಅನ್ನು ಆರಂಭಿಸಲು ಪ್ರಯತ್ನಿಸುವಂತಹ ಇತರ ದೋಷಗಳಿಗೆ `1`.

| ಆಯ್ಕೆ | ಏನು ಮಾಡುತ್ತದೆ | ಡೀಫಾಲ್ಟ್ |
| --- | --- | --- |
| `--model <model>` | ಏಜೆಂಟ್‌ನ ಮಾಡೆಲ್; ಆಯ್ಕೆಯಲ್ಲಿ ಆ ಮಾಡೆಲ್‌ನ ವಾರದ ಅವಧಿಯನ್ನೂ ಎಣಿಸಲಾಗುತ್ತದೆ | ಖಾತೆಯ ಡೀಫಾಲ್ಟ್ ಮಾಡೆಲ್ |
| `--resume <id>` | ಹಿಂದಿನ ಏಜೆಂಟ್‌ನ ಸಂಭಾಷಣೆಯನ್ನು ಮುಂದಿನ ಕಾರ್ಯದೊಂದಿಗೆ ಮುಂದುವರಿಸುತ್ತದೆ (ಸೆಷನ್ ID ಅದರ ಮೊದಲ ಮತ್ತು ಕೊನೆಯ ಸಾಲಿನಲ್ಲಿರುತ್ತದೆ) | ಆಫ್ |
| `--json` | ಖಾತೆ, ಸೆಷನ್, ಉತ್ತರ ಮತ್ತು ಅದು ಯಾವ ಖಾತೆಗಳಾಗಿ ರನ್ ಆಯಿತೋ ಅವನ್ನು ಮುದ್ರಿಸುತ್ತದೆ | ಆಫ್ |
| `--max-usage <1-100>` | ಈ ಬಳಕೆಗಿಂತ ಕೆಳಗಿರುವ ಖಾತೆಗಳಿಗೆ ಆದ್ಯತೆ | `auto_max_usage`, ಇಲ್ಲದಿದ್ದರೆ 100 |
| `--strategy headroom\|expiring\|balance` | [ಆಯ್ಕೆ ನಿಯಮ](/features/next#auto) | `auto_strategy`, ಇಲ್ಲದಿದ್ದರೆ `headroom` |
| `--cross-org` | ಬೇರೆ ಸಂಸ್ಥೆಗಳ ಖಾತೆಗಳಾಗಿಯೂ ರನ್ ಮಾಡುತ್ತದೆ | `cross_org`, ಇಲ್ಲದಿದ್ದರೆ ಆಫ್ |
| `--wait[=<duration>]` | ಯಾವ ಖಾತೆಯಲ್ಲೂ ಅವಕಾಶ ಇಲ್ಲದಿದ್ದಾಗ, ಮೊದಲ ಖಾತೆ ರೀಸೆಟ್ ಆಗುವವರೆಗೆ, ಗರಿಷ್ಠ ಇಷ್ಟು ಸಮಯ ಕಾಯುತ್ತದೆ | ಆಫ್; ಮೌಲ್ಯವಿಲ್ಲದೆ ನೀಡಿದರೆ `5h` |
| `--dry-run` | ಆಯ್ಕೆಮಾಡಲಿರುವ ಖಾತೆಗಾಗಿ ಕಮಾಂಡ್ ಅನ್ನು, ಅದನ್ನು ರನ್ ಮಾಡದೆ, ಮುದ್ರಿಸುತ್ತದೆ | ಆಫ್ |

## ಇದು ಹೇಗೆ ಕೆಲಸ ಮಾಡುತ್ತದೆ

1. **ಕರೆದ ಖಾತೆಯನ್ನು ಬಿಡಲಾಗುತ್ತದೆ.** `ccam agent` ಅನ್ನು ಯಾವ ಖಾತೆಯಿಂದ ಕರೆಯಲಾಗುತ್ತದೋ ಆ ಖಾತೆ (ccam ಆರಂಭಿಸಿದ ಸೆಷನ್‌ನ ಖಾತೆ, ಇಲ್ಲದಿದ್ದರೆ ಈ ಫೋಲ್ಡರ್ ಆರಂಭಿಸುವ ಖಾತೆ) ಎಂದಿಗೂ ಏಜೆಂಟ್ ಅನ್ನು ರನ್ ಮಾಡುವುದಿಲ್ಲ, ಹಾಗೆಯೇ ಅದೇ Claude ಖಾತೆಗೆ ಲಾಗಿನ್ ಆಗಿರುವ ಇನ್ನೊಂದು ಫೋಲ್ಡರ್ ಕೂಡ ರನ್ ಮಾಡುವುದಿಲ್ಲ, ಏಕೆಂದರೆ ಅದು ಅದರ ಮಿತಿಗಳನ್ನು ಹಂಚಿಕೊಳ್ಳುತ್ತದೆ. `--cross-org` ಬೇರೆ ರೀತಿ ಹೇಳದಿದ್ದರೆ, ಏಜೆಂಟ್ ಕರೆದ ಖಾತೆಯ [ಸಂಸ್ಥೆಯಲ್ಲೇ](/features/next#auto) ಉಳಿಯುತ್ತದೆ.
2. **ಇದು `ccam pick` ನಂತೆ ಆಯ್ಕೆಮಾಡುತ್ತದೆ.** ಬಳಕೆಯನ್ನು [`ccam pick`](/features/pick) ನೋಡುವಂತೆಯೇ ನೋಡಲಾಗುತ್ತದೆ, ಮತ್ತು ಒಂದರಿಂದ ಇನ್ನೊಂದು 2 ನಿಮಿಷಗಳ ಒಳಗೆ ಆರಂಭವಾದ ಏಜೆಂಟ್‌ಗಳಿಗೆ, ಅವಕಾಶ ಇರುವ ಸಾಕಷ್ಟು ಖಾತೆಗಳಿರುವವರೆಗೆ, ಬೇರೆ ಬೇರೆ ಖಾತೆಗಳು ಸಿಗುತ್ತವೆ.
3. **ಇದು ಸೆಷನ್‌ನ ಅನುಮತಿಗಳೊಂದಿಗೆ ರನ್ ಆಗುತ್ತದೆ, ಎಂದಿಗೂ ಅದಕ್ಕಿಂತ ಹೆಚ್ಚಿಲ್ಲ.** `claude -p` ನಲ್ಲಿ ಟೂಲ್ ಅನ್ನು ಅನುಮತಿಸಲು ಯಾರೂ ಇರುವುದಿಲ್ಲ, ಹೀಗಾಗಿ ಏಜೆಂಟ್‌ಗೆ ಅದನ್ನು ಕರೆದ ಸೆಷನ್‌ನ ಅನುಮತಿ ಮೋಡ್ ಮತ್ತು effort ಸಿಗುತ್ತವೆ. ಟರ್ಮಿನಲ್‌ನಿಂದ ರನ್ ಮಾಡಿದಾಗ, Claude Code ನ ಡೀಫಾಲ್ಟ್ ಮೋಡ್ ಮತ್ತು ನಿಮ್ಮ ಸೆಟ್ಟಿಂಗ್‌ಗಳ ಅನುಮತಿ ನಿಯಮಗಳು ಅನ್ವಯಿಸುತ್ತವೆ. ಹೆಚ್ಚಿನ ಅನುಮತಿ ನೀಡುವ ಯಾವ ಆಯ್ಕೆಯೂ `ccam agent` ನಲ್ಲಿ ಇಲ್ಲ.
4. **ಬಳಕೆಯ ಮಿತಿಯಲ್ಲಿ, ಸಂಭಾಷಣೆ ಮುಂದುವರಿಯುತ್ತದೆ.** ಏಜೆಂಟ್‌ನ ಖಾತೆ ತನ್ನ ಮಿತಿ ತಲುಪಿದಾಗ, [ಪ್ಲಗಿನ್ ಹುಕ್](/features/usage#the-limit-record) ಮಾಡುವಂತೆಯೇ ccam ಮಿತಿಯನ್ನು ದಾಖಲಿಸುತ್ತದೆ ಮತ್ತು ಅದೇ ಸಂಭಾಷಣೆಯನ್ನು ಹೆಚ್ಚು ಅವಕಾಶ ಇರುವ ಖಾತೆಯಾಗಿ ಮುಂದುವರಿಸುತ್ತದೆ: Claude Code ಅದನ್ನು ಅಲ್ಲಿಗೆ ನಕಲಿಸುತ್ತದೆ (`--resume <file> --fork-session`), ಈ ಮೊದಲ ಸಂದೇಶದೊಂದಿಗೆ: "Your usage limit was reached and ccam moved this conversation to another account. Continue the task you were working on when the limit was reached; do not repeat work that is already complete." ಪ್ರತಿ ಖಾತೆಯನ್ನು ಒಮ್ಮೆ ಪ್ರಯತ್ನಿಸಲಾಗುತ್ತದೆ.
5. **ಪ್ರತಿ ಏಜೆಂಟ್ ಸಂಭಾಷಣೆಯನ್ನು ದಾಖಲಿಸಲಾಗುತ್ತದೆ**, `~/.local/state/ccam/agent/<session id>.json` ನಲ್ಲಿ (30 ದಿನಗಳು). `--resume <id>` ಅದನ್ನು ಅದರ ಫೋಲ್ಡರ್‌ನಲ್ಲಿ ಮುಂದುವರಿಸುತ್ತದೆ: ಅದನ್ನು ರನ್ ಮಾಡಿದ ಖಾತೆಯಲ್ಲಿ ಇನ್ನೂ ಅವಕಾಶ ಇದ್ದರೆ ಆ ಖಾತೆಯಾಗಿ, ಇಲ್ಲದಿದ್ದರೆ ಇನ್ನೊಂದು ಖಾತೆಯಾಗಿ. [`ccam next --continue`](/features/next) ಏಜೆಂಟ್ ಸಂಭಾಷಣೆಗಳನ್ನು ಬಿಟ್ಟುಬಿಡುತ್ತದೆ, ಹೀಗಾಗಿ ಅದು ನಿಮ್ಮ ಸಂಭಾಷಣೆಯನ್ನೇ ಮುಂದುವರಿಸುತ್ತಿರುತ್ತದೆ.

## ಸುರಕ್ಷತೆ ಮತ್ತು ವಿಶೇಷ ಸಂದರ್ಭಗಳು

- ಏಜೆಂಟ್ ತನ್ನದೇ ಏಜೆಂಟ್‌ಗಳನ್ನು ಆರಂಭಿಸಲಾರದು: ccam ಅದನ್ನು `CCAM_AGENT=1` ನಿಂದ ಗುರುತಿಸುತ್ತದೆ, ಮತ್ತು ಅಲ್ಲಿ `ccam agent` ರನ್ ಆಗಲು ನಿರಾಕರಿಸುತ್ತದೆ.
- `ccam agent` ಅನ್ನು ನಿಲ್ಲಿಸಿದರೆ (Ctrl+C, ಸಿಗ್ನಲ್, ಅಥವಾ Claude Code ಕಮಾಂಡ್ ಅನ್ನು ಅಡ್ಡಿಪಡಿಸಿದರೆ) ಏಜೆಂಟ್ ಕೂಡ ನಿಲ್ಲುತ್ತದೆ.
- ಏಜೆಂಟ್ ತನ್ನನ್ನು ಕರೆದ ಸಂಭಾಷಣೆಯನ್ನು ನೋಡುವುದಿಲ್ಲ, ತನ್ನ ಕಾರ್ಯವನ್ನು ಮಾತ್ರ ನೋಡುತ್ತದೆ.
- ಒಂದೇ ಫೈಲ್‌ಗಳನ್ನು ಒಂದೇ ಸಮಯದಲ್ಲಿ ಸಂಪಾದಿಸುವ ಏಜೆಂಟ್‌ಗಳು ಪರಸ್ಪರರ ಕೆಲಸವನ್ನು ತಿದ್ದಿಬರೆಯುತ್ತವೆ. ಪ್ರತಿಯೊಂದಕ್ಕೂ ಕಾರ್ಯದ ಅದರದೇ ಭಾಗವನ್ನು, ಅಥವಾ ಅದರದೇ git worktree ಅನ್ನು ನೀಡಿ.
- ಕರೆದ ಸೆಷನ್ ಇನ್ನೊಂದು ಖಾತೆಗೆ ಸ್ಥಳಾಂತರಗೊಂಡಾಗ ([`auto_switch`](/features/next#auto-switch)), ಅದು ಆರಂಭಿಸಿದ ಏಜೆಂಟ್‌ಗಳು ಅದರೊಂದಿಗೆ ನಿಲ್ಲುತ್ತವೆ. ಅವುಗಳ ಸಂಭಾಷಣೆಗಳು ಉಳಿಯುತ್ತವೆ: `--resume <id>` ಅವನ್ನು ಮುಂದುವರಿಸುತ್ತದೆ.
- `agent` ಒಂದು ಕಮಾಂಡ್ ಹೆಸರು, ಹೀಗಾಗಿ ಯಾವುದೇ ಹೊಸ ಖಾತೆಗೆ `agent` ಎಂದು ಹೆಸರಿಡಲಾಗದು; ಈಗಾಗಲೇ ಇರುವ ಖಾತೆ ಈಗಲೂ `ccam run agent` ಮೂಲಕ ಆರಂಭವಾಗುತ್ತದೆ.
