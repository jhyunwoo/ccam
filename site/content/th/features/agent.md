subagent ของ Claude Code เองทำงานในชื่อบัญชีของเซสชันที่เริ่มมัน จึงใช้โควตาของบัญชีนั้น `ccam agent "<task>"` รันงานด้วย `claude -p` ในโฟลเดอร์เดียวกันในชื่อบัญชีอื่นของคุณ แล้วพิมพ์คำตอบสุดท้ายของ Claude เมื่อเรียกจากเซสชัน Claude Code คำสั่งนี้จะทำงานเหมือน subagent ที่ใช้โควตาของบัญชีอื่น งานยาวงานเดียวจึงดำเนินต่อได้แม้เลยจุดที่บัญชีของเซสชันเองจะหมดโควตาไปแล้ว

**ที่นั่ง (seat) ของ Team และ Enterprise** `ccam agent` เลือกบัญชีเอง ภายในองค์กร Claude Team หรือ Enterprise เดียวกัน คำสั่งนี้จะรันงานบนที่นั่งอื่น ซึ่งอาจละเมิดข้อกำหนดของ Anthropic โปรดอ่าน[คำถามที่พบบ่อย](/docs/faq#am-i-allowed-to-use-several-claude-code-accounts) และสอบถามองค์กรของคุณและ Anthropic ก่อนที่จะพึ่งพาคำสั่งนี้

## การใช้งาน

Claude Code รันคำสั่งนี้ผ่านเครื่องมือ Bash ของตัวเอง เมื่อติดตั้ง[ปลั๊กอิน ccam](/docs/install#claude-code-plugin)แล้ว ให้ขอด้วยภาษาธรรมดา เช่น "ใช้บัญชีอื่นของฉันทำส่วนต่าง ๆ ของงานนี้" หรือเขียนไว้ใน CLAUDE.md ของคุณ skill ของปลั๊กอินจะบอก Claude Code ให้เริ่มแต่ละเอเจนต์ในเบื้องหลัง ให้เขียนงานที่เข้าใจได้ในตัวเอง และให้เอเจนต์ที่แก้ไขไฟล์ได้รับส่วนงานของตัวเองหรือ git worktree ของตัวเอง

```sh
ccam agent "find why TestParse fails and fix it; reply with what you changed"
ccam agent --model opus -- "-v breaks the parser: find out why"
ccam agent --json < task.md            # the task from standard input
ccam agent --resume 7f3c9a2e-… "now add a test for it"
ccam agent --wait=1h "…"               # nobody has room: wait for a reset
ccam --dry-run agent "…"               # the account and command it would run
```

```console
$ ccam agent "summarize what internal/usage does"
ccam: agent runs as work (12% of its 5 hours used); session 7f3c9a2e-5b1d-4c2a-9e8f-1a2b3c4d5e6f
internal/usage looks up the 5-hour and weekly usage of every account …
ccam: agent finished as work; follow up with: ccam agent --resume 7f3c9a2e-5b1d-4c2a-9e8f-1a2b3c4d5e6f "…"
```

คำตอบสุดท้ายของ Claude จะออกทางเอาต์พุตมาตรฐาน ส่วนบรรทัดที่ขึ้นต้นด้วย `ccam:` จะออกทางเอาต์พุตข้อผิดพลาดมาตรฐาน `--json` จะพิมพ์ `{account, session_id, result, is_error, accounts}` แทน โดย `accounts` แสดงรายการทุกบัญชีที่งานนั้นรันในชื่อ

รหัสออก: รหัสของ claude เอง (`0` เมื่อเอเจนต์ทำงานเสร็จ) `75` (`EX_TEMPFAIL`) เมื่อไม่มีบัญชีใดนอกจากบัญชีที่เรียกใช้ที่เหลือโควตา และ `1` สำหรับข้อผิดพลาดอื่น เช่น เอเจนต์พยายามเริ่มเอเจนต์อีกตัว

## ตัวเลือก

| ตัวเลือก | สิ่งที่ทำ | ค่าเริ่มต้น |
| --- | --- | --- |
| `--model <model>` | โมเดลของเอเจนต์ ช่วงรายสัปดาห์ของโมเดลนั้นจะถูกนับในการเลือกด้วย | โมเดลเริ่มต้นของบัญชี |
| `--resume <id>` | ดำเนินการสนทนาของเอเจนต์ก่อนหน้าต่อด้วยงานติดตามผล (session id ในบรรทัดแรกและบรรทัดสุดท้ายของเอเจนต์นั้น) | ปิด |
| `--json` | พิมพ์บัญชี เซสชัน คำตอบ และบัญชีที่งานรันในชื่อ | ปิด |
| `--max-usage <1-100>` | เลือกบัญชีที่ใช้งานต่ำกว่าค่านี้ก่อน | `auto_max_usage` หากไม่มีคือ 100 |
| `--strategy headroom\|expiring\|balance` | [กฎการเลือก](/features/next#auto) | `auto_strategy` หากไม่มีคือ `headroom` |
| `--cross-org` | รันในชื่อบัญชีขององค์กรอื่นด้วย | `cross_org` หากไม่มีคือปิด |
| `--wait[=<duration>]` | เมื่อไม่มีบัญชีใดเหลือโควตา ให้รอบัญชีแรกที่รีเซ็ต นานไม่เกินค่านี้ | ปิด; `5h` เมื่อระบุโดยไม่มีค่า |
| `--dry-run` | พิมพ์คำสั่งสำหรับบัญชีที่จะเลือก โดยไม่รัน | ปิด |

## วิธีการทำงาน

1. **ไม่ใช้บัญชีที่เรียกใช้** บัญชีที่เรียก `ccam agent` (บัญชีของเซสชันที่ ccam เริ่ม หรือบัญชีที่โฟลเดอร์นี้เริ่มใช้) จะไม่รันเอเจนต์เลย โฟลเดอร์อื่นที่เข้าสู่ระบบด้วยบัญชี Claude เดียวกันซึ่งใช้ขีดจำกัดร่วมกันก็เช่นกัน เอเจนต์จะอยู่ใน[องค์กร](/features/next#auto)ของบัญชีที่เรียกใช้ เว้นแต่ `--cross-org` จะระบุเป็นอย่างอื่น
2. **เลือกแบบเดียวกับ `ccam pick`** การใช้งานจะถูกตรวจแบบเดียวกับที่ [`ccam pick`](/features/pick) ทำ และเอเจนต์ที่เริ่มห่างกันไม่เกิน 2 นาทีจะได้บัญชีต่างกันตราบใดที่มีบัญชีที่เหลือโควตามากพอ
3. **รันด้วยสิทธิ์ของเซสชัน ไม่มากไปกว่านั้น** ใน `claude -p` ไม่มีใครคอยอนุญาตเครื่องมือ เอเจนต์จึงได้โหมดสิทธิ์และระดับ effort ของเซสชันที่เรียกมัน หากรันจากเทอร์มินัล จะใช้โหมดเริ่มต้นของ Claude Code และกฎสิทธิ์ในการตั้งค่าของคุณ `ccam agent` ไม่มีตัวเลือกที่ให้สิทธิ์มากกว่านั้น
4. **เมื่อถึงขีดจำกัดการใช้งาน การสนทนาจะดำเนินต่อ** เมื่อบัญชีของเอเจนต์ถึงขีดจำกัด ccam จะบันทึกขีดจำกัดแบบเดียวกับที่[hook ของปลั๊กอิน](/features/usage#the-limit-record)ทำ และดำเนินการสนทนาเดิมต่อในชื่อบัญชีที่เหลือโควตามากที่สุด: Claude Code จะคัดลอกการสนทนาไปที่นั่น (`--resume <file> --fork-session`) โดยมีข้อความแรกว่า "Your usage limit was reached and ccam moved this conversation to another account. Continue the task you were working on when the limit was reached; do not repeat work that is already complete." แต่ละบัญชีจะถูกลองเพียงครั้งเดียว
5. **ทุกการสนทนาของเอเจนต์จะถูกบันทึก**ไว้ใน `~/.local/state/ccam/agent/<session id>.json` (30 วัน) `--resume <id>` จะดำเนินการสนทนานั้นต่อในโฟลเดอร์ของมัน ในชื่อบัญชีที่รันมันหากบัญชีนั้นยังเหลือโควตา มิฉะนั้นในชื่อบัญชีอื่น [`ccam next --continue`](/features/next) จะไม่นับการสนทนาของเอเจนต์ จึงยังคงดำเนินการสนทนาของคุณต่อ

## ความปลอดภัยและกรณีพิเศษ

- เอเจนต์ไม่สามารถเริ่มเอเจนต์ของตัวเองได้: ccam ทำเครื่องหมายเอเจนต์ด้วย `CCAM_AGENT=1` และ `ccam agent` จะปฏิเสธที่จะรันในนั้น
- การหยุด `ccam agent` (Ctrl+C สัญญาณ หรือ Claude Code ขัดจังหวะคำสั่ง) จะหยุดเอเจนต์ด้วย
- เอเจนต์ไม่เห็นการสนทนาที่เรียกมัน เห็นเพียงงานของตัวเอง
- เอเจนต์ที่แก้ไขไฟล์เดียวกันพร้อมกันจะเขียนทับงานของกันและกัน ให้แต่ละตัวได้ส่วนงานของตัวเอง หรือได้ git worktree ของตัวเอง
- เมื่อเซสชันที่เรียกใช้ย้ายไปยังบัญชีอื่น ([`auto_switch`](/features/next#auto-switch)) เอเจนต์ที่เซสชันนั้นเริ่มจะหยุดไปด้วย การสนทนาของเอเจนต์ยังคงอยู่: `--resume <id>` จะดำเนินการสนทนาเหล่านั้นต่อ
- `agent` เป็นชื่อคำสั่ง จึงไม่สามารถตั้งชื่อบัญชีใหม่ว่า `agent` ได้ บัญชีที่มีอยู่แล้วซึ่งใช้ชื่อนี้ยังเริ่มได้ด้วย `ccam run agent`
