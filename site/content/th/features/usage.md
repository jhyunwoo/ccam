`ccam usage` แสดงว่าแต่ละบัญชีใช้ขีดจำกัดแต่ละแบบไปแล้วเท่าไร ได้แก่ ขีดจำกัดแบบ 5 ชั่วโมง ขีดจำกัดรายสัปดาห์ และขีดจำกัดรายสัปดาห์เฉพาะของแต่ละโมเดล (เช่น Fable) แต่ละขีดจำกัดจะมีแถบและเวลาที่เหลือจนกว่าจะรีเซ็ต ใช้ก่อนเริ่มงานที่ใช้เวลานาน หรือเมื่อ Claude Code แจ้งว่าใกล้ถึงขีดจำกัด เพื่อดูว่าบัญชีใดยังเหลือโควตา `ccam statusline` คือคำสั่งแถบสถานะสำหรับ Claude Code: แสดงชื่อบัญชีและการใช้งานภายใน Claude Code และบันทึกตัวเลขไว้ให้ `ccam usage` ส่วนโทเค็นและค่าใช้จ่ายโดยประมาณที่อยู่เบื้องหลังการใช้งานนั้น `ccam ccusage` จะรัน [ccusage](https://ccusage.com) กับการสนทนาของทุกบัญชี ([ดูด้านล่าง](#tokens-and-costs-ccam-ccusage))

## การใช้งาน

```sh
ccam usage                  # every account, once
ccam u                      # the same, shorter
ccam usage --watch          # redraw every 60 seconds until Ctrl+C
ccam usage --watch=10       # redraw every 10 seconds
ccam usage -v               # add where the numbers came from
ccam usage --json           # machine-readable, one object per account
ccam usage --source cache   # saved numbers only, no network
ccam usage --refresh        # also renew expired logins of accounts that are not running
ccam usage --source claude  # let Claude Code look it up: ccam sends no token
ccam statusline install     # set the status line in every account's settings.json
```

แต่ละบัญชีจะมีหนึ่งบรรทัดที่แสดงหมายเลข ชื่อ และอายุของตัวเลข ส่วน `(cached)` หมายความว่าตัวเลขมาจากไฟล์ที่บันทึกไว้ ไม่ใช่จาก endpoint ใต้บรรทัดนั้น แต่ละขีดจำกัดมีหนึ่งบรรทัดที่แสดงแถบขนาด 20 ช่อง เปอร์เซ็นต์ และเวลาที่เหลือจนกว่าช่วงนั้นจะรีเซ็ต: `5-hour`, `Weekly` (ทุกโมเดล) แล้วตามด้วยช่วงรายสัปดาห์เฉพาะของแต่ละโมเดล เช่น `Fable` ช่วงที่บัญชีไม่มีจะแสดง `-` เปอร์เซ็นต์จะเปลี่ยนเป็นสีเหลืองที่ 80% และเป็นสีแดงที่ 100%

หาก Claude Code ปฏิเสธคำขอเพราะช่วงหนึ่งเต็ม ช่วงนั้นจะแสดง 100% จนกว่าจะรีเซ็ต ไม่ว่าตัวเลขที่บันทึกไว้จะเป็นเท่าใด (ดู[บันทึกขีดจำกัด](#the-limit-record)) บนเทอร์มินัล ทุกบัญชีจะปรากฏทันทีเป็น `fetching…` และบรรทัดของบัญชีจะถูกวาดเมื่อบัญชีนั้นได้รับคำตอบ

บรรทัดสุดท้าย ซึ่งแสดงเฉพาะเมื่อคุณมีมากกว่าหนึ่งบัญชี ระบุบัญชีที่ [`ccam next --auto`](/features/next) จะเลือก โดยใช้กฎชุดเดียวกัน:

- `auto_max_usage` และ `auto_strategy`
- เซสชันที่กำลังทำงาน
- เฉพาะบัญชีในองค์กรของบัญชีที่ใช้ล่าสุด เว้นแต่จะตั้ง `cross_org` ไว้
- ข้ามทุกช่วงเวลาที่ถึง 100% บัญชีที่ใช้โควตารายสัปดาห์เต็มแล้วจึงไม่ถูกระบุเลย

เมื่อใช้กลยุทธ์ `headroom` ซึ่งเป็นค่าเริ่มต้น บรรทัดนั้นจะเป็น `→ Most headroom: <name>` ส่วนเมื่อใช้ `expiring` หรือ `balance` จะบอกเหตุผล เช่น `→ next --auto picks personal: its 5-hour window resets first, in 1h 12m (40% of its 5 hours used)`

**ที่นั่ง (seat) ของ Team และ Enterprise** การเลือกบัญชีอัตโนมัติ (`ccam next`, `--fallback`, `ccam pick`, ปุ่ม `n` ในแดชบอร์ด และ [`auto_switch`](/features/next#auto-switch) เมื่อคุณเปิดใช้) จะสลับระหว่างที่นั่งต่าง ๆ ในองค์กร Claude Team หรือ Enterprise เดียวกันด้วย ซึ่งอาจละเมิดข้อกำหนดของ Anthropic โปรดอ่าน[คำถามที่พบบ่อย](/docs/faq#am-i-allowed-to-use-several-claude-code-accounts) และสอบถามองค์กรของคุณและ Anthropic ก่อนที่จะพึ่งพาการเลือกอัตโนมัติ

บัญชีที่ยังไม่ได้เข้าสู่ระบบจะแสดง `not logged in → ccam login <name>` และบัญชีที่ใช้ API key จะแสดง `no limits (API)` โทเค็นการเข้าถึงที่หมดอายุจะแสดง ``access token expired; `ccam <name>` renews it when it starts`` ไว้เหนือตัวเลขที่บันทึกไว้หากมี: Claude Code จะต่ออายุให้เมื่อเริ่มครั้งถัดไป การเข้าสู่ระบบที่หมดอายุทั้งหมด เพราะ refresh token หมดอายุ หรือ Claude Code ล้างการเข้าสู่ระบบหลังจากเซิร์ฟเวอร์ปฏิเสธ จะแสดง `` login expired → `ccam login <name>` ``

หลังจาก `ccam statusline install` แล้ว Claude Code จะแสดงบรรทัดอย่าง `[work] · Opus · 5h 24% · 7d 41%`

## ตัวเลือก

| ตัวเลือก | สิ่งที่ทำ | ค่าเริ่มต้น |
| --- | --- | --- |
| `--json` | พิมพ์รายงานเป็น JSON: `name`, `slot`, `status`, `limits` (พร้อม `credits` เมื่อบัญชีเปิดใช้เครดิตการใช้งาน), `source`, `at`, `error` และ `limited` กับ `limited_windows` เมื่อบันทึกขีดจำกัดตั้งช่วงเป็น 100% เมื่อไม่มีบัญชีใดจะพิมพ์ `[]` | ปิด |
| `--watch[=N]` | วาดใหม่ทุก `N` วินาทีจนกว่าคุณจะกด Ctrl+C `--watch` อย่างเดียว หรือค่าที่เป็น 0 หรือน้อยกว่า หมายถึง 60 ค่าต้องอยู่หลัง `=`: `--watch 10` จะถูกปฏิเสธพร้อมคำแนะนำ | ปิด |
| `-v`, `--verbose` | เพิ่มบรรทัด `source:` ใต้แต่ละบัญชี: แหล่งที่มาของตัวเลข (endpoint การใช้งาน, Claude Code, แถบสถานะ, ไฟล์ที่บันทึกไว้ หรือขีดจำกัดการใช้งานที่ Claude Code รายงาน) เมื่อบันทึกขีดจำกัดมีผลเหนือตัวเลข จะมีบรรทัดอย่าง `Weekly full: Claude Code reported the usage limit 1h 0m ago, so 100% until the reset` ตามมา | ปิด |
| `--no-cache` | ไม่ใช้แคช 60 วินาทีและสอบถาม endpoint ใหม่ | ปิด |
| `--source live\|claude\|cache` | `live` สอบถาม endpoint ด้วยโทเค็นของบัญชี `claude` ให้ Claude Code เป็นผู้สอบถามเอง (ดูด้านล่าง) ส่วน `cache` แสดงเฉพาะตัวเลขที่บันทึกไว้ | `usage_source` หากไม่มีคือ `live` |
| `--refresh` | ต่ออายุ access token ที่หมดอายุ เฉพาะบัญชีที่ไม่ได้ทำงานอยู่ การต่ออายุอาจใช้เวลาถึง 30 วินาที | ปิด |
| `--dry-run` | ยอมรับ: `ccam usage` ไม่เปลี่ยนแปลงสิ่งใดนอกจากแคชของตัวเอง แต่จะถูกปฏิเสธเมื่อใช้ร่วมกับ `--refresh`: `--dry-run cannot be combined with --refresh, which rewrites login tokens` | ปิด |

ค่าอื่นของ `--source` จะล้มเหลวด้วย `--source must be live, claude or cache` `ccam usage` ไม่รับอาร์กิวเมนต์

### การใช้งานจาก Claude Code เอง

เมื่อตั้ง `usage_source = "claude"` ที่ด้านบนสุดของ `config.toml` (เหนือ `[[group]]`, `[[profile]]` หรือ `[[folder]]` ตัวแรก) หรือใช้ `--source claude` ccam จะไม่อ่านโทเค็นการเข้าสู่ระบบเลย สำหรับแต่ละบัญชี ccam จะเริ่ม `claude -p --input-format stream-json --output-format stream-json --verbose --safe-mode --no-session-persistence` ในโฟลเดอร์ของบัญชีนั้น และส่งคำขอ `get_usage` ของ Claude Code ทางอินพุตมาตรฐาน (Claude Code 2.1.270 ขึ้นไป) Claude Code จะสอบถามการใช้งานด้วยการเข้าสู่ระบบของตัวเองและตอบกลับด้วยช่วงเวลา 5 ชั่วโมง รายสัปดาห์ และของแต่ละโมเดล

`--safe-mode` ป้องกันไม่ให้ hook เซิร์ฟเวอร์ MCP และปลั๊กอินของบัญชีเริ่มทำงาน และไม่มีการบันทึกเซสชัน แต่ละบัญชีต้องเริ่ม Claude Code หนึ่งครั้ง (ราวหนึ่งวินาที) แหล่งนี้จึงช้ากว่า `live` ทุกบัญชีจะถูกสอบถามพร้อมกัน บัญชีละหมดเวลาที่ 20 วินาที และแคช 60 วินาทียังมีผลตามปกติ

การเข้าสู่ระบบที่โทเค็นการเข้าถึงหมดอายุแล้ว หรือจะหมดอายุภายใน 5 นาที จะได้เวลา 50 วินาที เพราะ Claude Code จะต่ออายุโทเค็นขณะเริ่ม และการต่ออายุที่ถูกตัดกลางคันอาจทำให้การเข้าสู่ระบบหายไป หาก ccam ยกเลิกการสอบถาม จะขอให้ Claude Code ออกด้วย SIGTERM เพื่อให้ Claude Code ทำการต่ออายุที่เริ่มไปแล้วให้เสร็จ (Windows ไม่มี SIGTERM บน Windows จึงยุติโปรเซสแทน)

การเข้าสู่ระบบที่หมดอายุทั้งหมดจะแสดง `` login expired → `ccam login <name>` `` โดยไม่เริ่ม Claude Code เลย ทั้งนี้ Claude Code ระบุว่าคำขอนี้ยังเป็นแบบทดลอง หากคำขอนี้หยุดตอบกลับ ccam จะแสดงตัวเลขที่บันทึกไว้และ `ccam doctor` จะรายงานให้ทราบ เมื่อ Claude Code ตอบว่าการสอบถามของตัวเองล้มเหลว ccam จะแสดงตัวเลขที่บันทึกไว้พร้อม `the usage endpoint gave Claude Code no usage (it may be refusing lookups for now)` ไม่ใช่แพ็กเกจที่ไม่มีขีดจำกัด

เมื่อใช้ `--dry-run` ccam จะไม่เริ่ม Claude Code เพราะ Claude Code เขียนลงในโฟลเดอร์ของบัญชี แต่จะแสดงตัวเลขที่บันทึกไว้แทน `usage_source` รับค่า `live` หรือ `claude` ส่วน `cache` เลือกได้เฉพาะกับ `--source`

`ccam statusline` อ่าน JSON ของแถบสถานะจาก Claude Code ทางอินพุตมาตรฐาน มีตัวเลือกเดียวคือ `--wrap <command>`: คำสั่งแถบสถานะที่มีอยู่ ซึ่งบรรทัดแรกของผลลัพธ์จะมีชื่อบัญชีนำหน้า `ccam statusline install` ไม่รับตัวเลือก ทั้งสองคำสั่งปฏิเสธ `--dry-run` ด้วย `` --dry-run is not supported by `ccam statusline`; nothing was changed ``

## โทเค็นและค่าใช้จ่าย: `ccam ccusage`

`ccam usage` แสดงว่าบัญชีใช้แต่ละขีดจำกัดไปแล้วเท่าไร ส่วน [ccusage](https://ccusage.com) นับโทเค็นและค่าใช้จ่ายโดยประมาณจากบันทึกการสนทนาของ Claude Code แทน เมื่อรันตามลำพัง ccusage จะหาบันทึกของ Claude Code เฉพาะใน `~/.claude` และ `~/.config/claude` (หรือในโฟลเดอร์ที่ `CLAUDE_CONFIG_DIR` ระบุ) บัญชีเดียวของ ccam ที่ ccusage มองเห็นได้จึงเป็นบัญชีที่นำเข้าในตำแหน่งเดิมที่ `~/.claude` `ccam ccusage` จะรัน ccusage โดยตั้ง `CLAUDE_CONFIG_DIR` เป็นโฟลเดอร์ของทุกบัญชีที่มีการสนทนา รายงานเดียวจึงครอบคลุมทุกบัญชี:

```sh
ccam ccusage                           # every account, ccusage's daily report
ccam ccusage daily --breakdown         # cost per model
ccam ccusage claude monthly --json     # Claude Code alone, as JSON
ccam ccusage -a work blocks --active   # one account's current 5-hour block
ccam ccusage -a work,side weekly       # these accounts, and any that share their history
```

ccam อ่านตัวเลือกของตัวเองก่อน: `-a` (`--account`) รับชื่อหรือหมายเลขบัญชี โดยคั่นด้วยเครื่องหมายจุลภาคหรือใส่ตัวเลือกนี้ซ้ำ และ `--dry-run` จะพิมพ์คำสั่งออกมาแทนการรัน ตั้งแต่อาร์กิวเมนต์แรกที่ไม่ใช่ตัวเลือกของ ccam เป็นต้นไป ทุกอย่างจะส่งต่อให้ ccusage ตามที่คุณพิมพ์ ยกเว้น `--config` สำหรับ `bun x` และ `npx` (ดูด้านล่าง) และ `ccam ccusage -- --help` จะแสดงวิธีใช้ของ ccusage เอง ccam จะรัน `ccusage` หากติดตั้งไว้ หากไม่มีจะใช้ `bun x ccusage` และหากยังไม่ได้อีกจะใช้ `npx ccusage@latest` สองตัวหลังนี้จะดาวน์โหลด ccusage มาจาก npm ทั้งสองตัวจะเริ่มทำงานในโฟลเดอร์ของ ccam เอง (`~/.local/state/ccam/ccusage`) ไม่ใช่ในโฟลเดอร์ที่คุณใช้อยู่ ดังนั้นโปรเจกต์ในโฟลเดอร์ที่คุณใช้อยู่จึงกำหนดไม่ได้ว่าทั้งสองตัวจะรันอะไร ไม่ว่าจะผ่าน `node_modules/.bin` ของโปรเจกต์, `bin` ใน `package.json` หรือรีจิสทรีใน `.npmrc` ของโปรเจกต์ และ `ccam --dry-run ccusage` จะแสดง `cd` เข้าไปยังโฟลเดอร์ของ ccam เมื่อไม่มีตัวใดใช้ได้เลย ccam จะบอกให้คุณติดตั้ง Node.js, Bun หรือ ccusage บน Linux และ macOS ccusage จะเข้ามาแทนที่ ccam ส่วนบน Windows ccam จะรอ ccusage และจบด้วยรหัสออกของ ccusage ภายใน WSL ccam จะข้าม `ccusage`, `bun` หรือ `npx` ที่อยู่บนไดรฟ์ของ Windows เพราะตัวนั้นจะทำงานเป็นโปรแกรม Windows โดยไม่มีโฟลเดอร์ของบัญชี

- รายงานครอบคลุมบัญชีที่โฟลเดอร์มีการสนทนา (มีโฟลเดอร์ `projects`) การสนทนาที่หลายบัญชีใช้ร่วมกันผ่านกลุ่มจะนับเพียงครั้งเดียว
- เมื่อใช้ `-a` บัญชีที่ใช้ประวัติการสนทนาร่วมกันผ่านกลุ่มจะพาการสนทนาของทั้งกลุ่มมาด้วย และ ccam จะบอกว่าเป็นของใคร: `ccam: work shares its conversation history with personal, so the report counts their conversations too`
- `blocks` แสดงช่วงเวลา 5 ชั่วโมง และแต่ละบัญชีมีช่วงเวลาของตัวเอง จึงให้ระบุบัญชีเพียงบัญชีเดียวสำหรับรายงานนี้ ดังตัวอย่างด้านบน
- ccusage จะรายงานเครื่องมือเขียนโค้ดอื่นที่พบด้วย เช่น Codex เว้นแต่คุณจะระบุเครื่องมือเดียว: `ccam ccusage claude daily` คือ Claude Code อย่างเดียว
- ขณะที่ ccam รัน ccusage อยู่ ccusage จะอ่านการตั้งค่าของตัวเอง (`ccusage.json`) จาก `./.ccusage` และโฟลเดอร์ของบัญชีเท่านั้น `--config` ใช้ระบุไฟล์อื่น: `ccam ccusage daily --config ~/.config/claude/ccusage.json` เนื่องจาก `bun x` และ `npx` เริ่มทำงานในโฟลเดอร์ของ ccam เอง เมื่อมี `./.ccusage/ccusage.json` อยู่และคุณไม่ได้ระบุไฟล์ใด ccam จะส่งไฟล์นี้ให้ทั้งสองตัวด้วย `--config` และจะส่ง `--config` ที่เป็นพาธสัมพัทธ์ไปเป็นพาธเต็ม จากนั้น ccusage จะอ่านพาธสัมพัทธ์อื่น ๆ เช่น `--pi-path` โดยอิงจากโฟลเดอร์ของ ccam ดังนั้นให้ระบุพาธเหล่านั้นแบบเต็ม
- ccusage จะอ่านโฟลเดอร์ที่พาธมีเครื่องหมายจุลภาคเป็นสองโฟลเดอร์ ccam จึงปฏิเสธโฟลเดอร์นั้นและบอกชื่อบัญชี ให้ใช้ `-a` เพื่อไม่รวมบัญชีนั้น
- `ccusage` เป็นคำสั่งของ ccam บัญชีที่ชื่อ ccusage จึงเริ่มได้ด้วย `ccam run ccusage` และ `ccam doctor` จะแจ้งเรื่องนี้

## วิธีการทำงาน

ตัวเลขของ `ccam usage` มาจากสองแหล่ง: endpoint การใช้งานที่ไม่มีเอกสารของ Anthropic `GET https://api.anthropic.com/api/oauth/usage` ซึ่งเรียกด้วยการเข้าสู่ระบบของแต่ละบัญชีเอง และค่าที่ Claude Code ส่งให้คำสั่งแถบสถานะ ทั้งหมดอยู่ใน `internal/usage`

1. ccam โหลด `config.toml` และสร้าง `usage.Account` หนึ่งรายการต่อบัญชี (`cli.usageCmd`) ได้แก่ โฟลเดอร์ `~/.local/share/ccam/profiles/<name>/` เครื่องหมายเซสชัน (เมื่อใช้ร่วมกับบันทึกของ Claude Code เองในโฟลเดอร์บัญชี จะบอกได้ว่าบัญชีกำลังทำงานอยู่หรือไม่) และบัญชีนั้นถูกนำเข้าในตำแหน่งเดิมหรือไม่
2. ccam สอบถามทุกบัญชีพร้อมกัน โดยใช้ goroutine หนึ่งตัวต่อบัญชี (`Fetcher.FetchAll`) ทุกตัวใช้ `http.Client` ตัวเดียวกัน การเชื่อมต่อไปยัง endpoint จึงถูกนำกลับมาใช้ การเชื่อมต่อใช้เวลาได้ 2 วินาที และแต่ละบัญชีมีเวลารวม 3 วินาที ไคลเอนต์ไม่ตาม redirect เพราะ redirect จะส่งโทเค็นซ้ำไปยังที่อื่น และอ่านคำตอบไม่เกิน 1 MB
3. เมื่อแต่ละบัญชีเสร็จ แถวของบัญชีนั้นจะถูกวาดใหม่ บัญชีที่ล้มเหลวหรือไม่ตอบกลับทันเวลาจะหันไปใช้ตัวเลขที่บันทึกไว้ บัญชีที่ช้าบัญชีเดียวจึงไม่ทำให้บัญชีอื่นต้องรอ

ในแผนภาพ แต่ละบัญชีถูกสอบถามใน goroutine ของตัวเอง และบัญชีที่หมดเวลาจะแสดงตัวเลขที่บันทึกไว้แทน:

<!-- motion:usage-fetch -->

`personal` และ `work` ตอบกลับทันเวลาและแสดงตัวเลขสด `side` ใช้เวลานานกว่า 3 วินาที ccam จึงแสดงตัวเลขที่บันทึกไว้ของบัญชีนี้แทน (`fallback()`) จากนั้น ccam วาดหนึ่งบล็อกต่อบัญชี (`usage.Table()`) และเลือกบัญชีที่ระบุไว้ในบรรทัดสุดท้าย (`usage.Best()`)

สำหรับบัญชีหนึ่ง ccam ตรวจตามลำดับต่อไปนี้ (`Fetcher.Fetch`):

<!-- motion:usage-cache -->

1. เมื่อใช้ `--source cache` จะไปที่ `fallback()` โดยตรง
2. หากไม่ได้ตั้ง `--no-cache` ผลลัพธ์สดใน `~/.local/state/ccam/usage/<name>.json` ที่วัดมาเมื่อไม่ถึง 60 วินาทีที่แล้ว (`CacheTTL`) จะถูกนำมาใช้ โดยประเมินตามเวลาปัจจุบัน: ช่วงที่รีเซ็ตไปแล้วตั้งแต่นั้นจะแสดง 0% และไฟล์ที่ลงเวลาไว้ล่วงหน้ากว่านาฬิกาจะไม่นับว่าใหม่ การรัน `ccam usage` สองครั้งติดกันจึงใช้คำขอเพียงหนึ่งครั้งต่อบัญชี
3. ccam อ่าน `.credentials.json` (หรือพวงกุญแจ (Keychain) ของ macOS) โดยไม่เปลี่ยนแปลง และถอดรหัสเฉพาะคีย์ `claudeAiOauth` (`readCredentials()`) หากไม่มีการเข้าสู่ระบบแบบสมัครสมาชิก จะแสดง `not logged in` หรือ `no limits (API)` เมื่อ `.claude.json` มี API key การเข้าสู่ระบบที่ refresh token หมดอายุแล้ว หรือที่ Claude Code ล้างไปแล้ว จะเป็น `` login expired → `ccam login <name>` `` และจะไม่ถูกสอบถาม
4. access token ที่หมดอายุจะไม่ถูกใช้ หากไม่ใส่ `--refresh` บัญชีจะแสดงตัวเลขที่บันทึกไว้พร้อม ``access token expired; `ccam <name>` renews it when it starts``
5. ในกรณีอื่น ccam จะเรียก endpoint สถานะ 401 หรือ 403 นับเป็นการเข้าสู่ระบบที่หมดอายุ (`login expired: authentication failed (401)`) ส่วนสถานะอื่นหรือเนื้อหาที่อ่านไม่ได้นับเป็นข้อผิดพลาด และทั้งสองกรณีจะหันไปใช้ตัวเลขที่บันทึกไว้ การสอบถามที่ถูกยุติด้วย Ctrl+C จะแสดง `cancelled` สถานะ 429 หมายความว่า endpoint ได้รับคำขอสำหรับบัญชีนี้มากเกินไป: ccam จะเขียน `<name>.pause` พร้อมเวลาที่จะถามอีกครั้ง (`Retry-After` หรือ 5 นาที สูงสุดหนึ่งชั่วโมง) แสดงตัวเลขที่บันทึกไว้พร้อม `rate limited by the usage endpoint; asking again after 15:10` และจะไม่เรียก endpoint สำหรับบัญชีนั้นจนถึงเวลานั้น แม้จะใส่ `--no-cache` ก็ตาม การลองใหม่ทันทีจะยิ่งทำให้การจำกัดอัตรายืดเยื้อออกไป
6. คำตอบที่ถูกต้องจะถูกเขียนลงใน `<name>.json` พร้อมเวลาที่วัด

สำหรับตัวเลขที่บันทึกไว้ ccam ใช้ผลการสอบถามที่บันทึกไว้ล่าสุด (`<name>.json` หรือ `<name>.claude.json` จากการสอบถามผ่าน Claude Code) และเมื่อ `<name>.statusline.json` ถูกเขียนหลังจากนั้น จะนำช่วง 5 ชั่วโมงและรายสัปดาห์ของแถบสถานะมาวางทับ (`fallback()`) ส่วนช่วงของแต่ละโมเดลซึ่งแถบสถานะไม่มี จะคงไว้ตามที่การสอบถามบันทึกไว้ ก่อนแสดงตัวเลขที่บันทึกไว้ จะตรวจเวลารีเซ็ตของแต่ละช่วง: ช่วงที่รีเซ็ตไปแล้วหลังจากบันทึกตัวเลขจะแสดงเป็น 0% เพราะเปอร์เซ็นต์เดิมใช้ไม่ได้แล้ว นี่คือเหตุผลที่ `personal` ด้านบนแสดง `0%` โดยไม่มีเวลารีเซ็ต

endpoint มีรูปแบบคำตอบสองแบบ แบบใหม่มีอาร์เรย์ `limits` ที่มีรายการ `session` (5 ชั่วโมง) `weekly_all` และ `weekly_scoped` (แยกตามโมเดล) แบบเก่ามีออบเจ็กต์ `five_hour`, `seven_day`, `seven_day_opus` และ `seven_day_sonnet` ccam อ่านได้ทั้งสองแบบ (`ParseLive`): อาร์เรย์ `limits` มีผลเหนือกว่า และออบเจ็กต์แบบเก่าจะเติมส่วนที่อาร์เรย์ไม่ครอบคลุม เนื้อหาที่ไม่มีขีดจำกัดเลยจะถูกรายงานว่ารูปแบบเปลี่ยนไป ซึ่ง `ccam doctor` จะแจ้งให้คุณทราบ

### บันทึกขีดจำกัด

เมื่อ Claude Code หยุดเทิร์นหนึ่งเพราะถึงขีดจำกัดการใช้งาน hook ของ[ปลั๊กอิน ccam](/docs/install#claude-code-plugin)จะอ่านคำขอที่ถูกปฏิเสธจากการสนทนา: ช่วงใดเต็ม (5 ชั่วโมง รายสัปดาห์ Opus หรือ Sonnet) และจะรีเซ็ตเมื่อใด แล้วเขียนข้อมูลนั้นลงใน `~/.local/state/ccam/usage/<name>.limit.json` ccam จะนำบันทึกนี้ไปใช้เหนือข้อมูลอื่นทั้งหมดที่รู้จากทุกแหล่ง (`Fetch`): ทุกช่วงในบันทึกจะนับเป็น 100% จนกว่าจะรีเซ็ต ไม่ว่าตัวเลขที่บันทึกไว้จะเก่าหรือต่ำเพียงใด ดังนั้น `ccam next --auto`, `ccam pick`, `--fallback` และ [`auto_switch`](/features/next#auto-switch) จะไม่เลือกบัญชีนั้นอีกก่อนถึงเวลานั้น

เมื่อไม่รู้ข้อมูลอื่นเลย บัญชีจะแสดงเพียงบันทึกนี้ (`source: the usage limit Claude Code reported` เมื่อใช้ `-v`) เซสชันที่ไม่มีคนดูแล (การรัน `-p` และเซสชันเบื้องหลัง) จะไม่เขียนบันทึก และการหยุดที่องค์กรตั้งไว้ (เช่น เมื่อองค์กรใช้งานหมด หรือขีดจำกัดของกลุ่มเป็น $0) ก็ไม่เขียนเช่นกัน เพราะผู้ดูแลยกเลิกได้ทุกเมื่อ `ccam login` ไปยังบัญชี Claude อื่นจะทิ้งบันทึกนี้ และการลบไฟล์ก็ล้างบันทึกได้เช่นกัน

### การต่ออายุโทเค็น

refresh token มีการหมุนเวียน: การต่ออายุหนึ่งครั้งจะได้ refresh token ใหม่และทำให้ตัวเดิมใช้ไม่ได้ หาก ccam ต่ออายุการเข้าสู่ระบบในขณะที่ Claude Code กำลังทำงานด้วยบัญชีเดียวกัน เซสชันนั้นจะถูกออกจากระบบ ดังนั้น `ccam usage` จึงอ่านโทเค็นแต่ไม่เคยเขียน เว้นแต่คุณจะใส่ `--refresh` จากนั้น ccam (`Fetcher.refresh`) จะ:

1. ปฏิเสธบัญชีที่ลงทะเบียนไว้ในตำแหน่งเดิมด้วย `ccam import` เพราะ `claude` แบบปกติอาจใช้การเข้าสู่ระบบนั้นโดยที่ ccam ไม่รู้
2. ปฏิเสธการเข้าสู่ระบบที่เก็บไว้ในพวงกุญแจ (Keychain) ของ macOS
3. ถือไฟล์ล็อก `~/.local/state/ccam/locks/profile-<name>.refresh.lock` เพื่อไม่ให้โปรเซส ccam สองตัวต่างก็ต่ออายุโทเค็นเดียวกัน ขณะที่ล็อกถูกถืออยู่ บัญชีจะแสดง `token not renewed: another ccam process is using this login right now (a refresh, rename, remove or logout)` ส่วน `ccam rename`, `remove` และ `logout` ก็ถือล็อกนี้เช่นกัน และจะปฏิเสธขณะที่การต่ออายุกำลังดำเนินอยู่
4. ภายใต้ล็อก จะปฏิเสธหากมีเซสชันของบัญชีกำลังทำงาน ไม่ว่าจะเริ่มด้วยวิธีใด (ผ่าน ccam, `claude` แบบปกติ, IDE หรือเซสชันเบื้องหลังและ daemon ที่อยู่เบื้องหลังซึ่งต่ออายุการเข้าสู่ระบบเอง) และข้ามคำขอหากโปรเซสอื่นต่ออายุโทเค็นไปแล้ว
5. ไม่ส่งอะไรเลยขณะที่ Claude Code ถือล็อกการต่ออายุของตัวเองในโฟลเดอร์บัญชี (`.oauth_refresh.lock`, `<folder>.lock`): เพราะ Claude Code กำลังต่ออายุการเข้าสู่ระบบนั้นอยู่พอดี
6. ส่ง refresh token ไปยัง endpoint ของโทเค็นและรอคำตอบไม่เกิน 30 วินาที ซึ่งเป็นเวลาที่ Claude Code ให้กับการต่ออายุของตัวเอง เมื่อส่งไปแล้ว คำขอจะไม่ถูกขัดจังหวะเลย แม้แต่ด้วย Ctrl+C เพราะเซิร์ฟเวอร์อาจหมุนเวียน refresh token ไปแล้ว และมีเพียงคำตอบเท่านั้นที่มีการเข้าสู่ระบบใหม่ Ctrl+C หรือ hangup จะยุติการสอบถามอื่น ๆ และ ccam จะออก (ด้วยรหัส 130 หลัง Ctrl+C) เมื่อบันทึกคำตอบแล้ว
7. บันทึกภายใต้ล็อกการเขียนของ Claude Code (`.storage-write.lock`) และเปลี่ยนเฉพาะฟิลด์โทเค็นของ `.credentials.json` ตามสภาพในขณะนั้น: สิ่งที่ Claude Code เขียนไว้ระหว่างนั้น (การลงชื่อเข้าใช้ MCP) จะยังคงอยู่ การเข้าสู่ระบบที่ Claude Code ต่ออายุไปในระหว่างนั้นจะถูกเก็บไว้ และการออกจากระบบจะไม่ถูกย้อนกลับเลย เมื่อคำตอบระบุอายุของ refresh token ใหม่ จะถูกเก็บเป็น `refreshTokenExpiresAt` แบบเดียวกับที่ Claude Code ทำ

การต่ออายุที่ไม่สำเร็จจะบอกเหตุผลไว้ในบรรทัดของบัญชีหรือเหนือตัวเลขที่บันทึกไว้ เช่น `token not renewed: a session is running` หรือ `login may be lost: …` เมื่อส่งคำขอไปแล้วแต่ใช้หรือบันทึกคำตอบไม่ได้ พร้อมคำแนะนำให้รัน `ccam login <name>` หาก Claude Code ขอให้คุณเข้าสู่ระบบหลังจากนั้น

### ตัวเก็บข้อมูลจากแถบสถานะ

Claude Code รันคำสั่งแถบสถานะและส่งเอกสาร JSON ให้ทางไปป์ ccam อ่านชื่อโมเดลและ `rate_limits` จากเอกสารนั้น:

<!-- motion:usage-statusline -->

1. ccam หาบัญชีจาก `CCAM_PROFILE` ซึ่ง ccam ตั้งไว้เมื่อเริ่ม Claude Code หรือหากไม่มีจะจับคู่ `CLAUDE_CONFIG_DIR` กับโฟลเดอร์ของบัญชี (`runStatusline`)
2. ccam อ่าน `rate_limits.five_hour` และ `rate_limits.seven_day` (`ParseStatusLine`) JSON จะไม่มีขีดจำกัดอัตราสำหรับบัญชีที่ใช้ API key หรือก่อนคำตอบแรกของเซสชัน ในกรณีนั้นจะไม่บันทึกสิ่งใด
3. ccam เขียน `~/.local/state/ccam/usage/<name>.statusline.json` (`SaveStatusLine`) ซึ่ง `ccam usage` จะใช้เมื่อ endpoint ไม่ตอบกลับ
4. ccam พิมพ์ `[name] · model · 5h N% · 7d N%` เมื่อใช้ `--wrap` จะรันคำสั่งของคุณผ่าน `sh -c` ด้วยอินพุตเดียวกัน แล้วพิมพ์เอาต์พุตแบบเดียวกับที่ Claude Code แสดงแถบสถานะ: ทุกบรรทัดที่ไม่ว่าง โดยมี `[name]` อยู่หน้าบรรทัดแรก คำสั่งที่ล้มเหลวจะแสดงเพียงชื่อบัญชี บน Windows จะรันคำสั่งแบบเดียวกับที่ Claude Code ทำ: ด้วย Git Bash หากติดตั้งไว้ มิฉะนั้นใช้ PowerShell
5. เมื่อการใช้งาน 5 ชั่วโมงหรือรายสัปดาห์อยู่ที่ 90% ขึ้นไปและมีบัญชีอื่นอยู่ บรรทัดจะลงท้ายด้วย `→ ccam next --auto --continue` เช่น `[work] · Opus · 5h 93% · 7d 41% · → ccam next --auto --continue`

คำสั่งที่ถูกครอบไม่มีการจำกัดเวลาของตัวเอง: Claude Code ให้เวลาคำสั่งแถบสถานะ 10 นาที และหยุดการรันเมื่อการอัปเดตที่ใหม่กว่าเริ่มขึ้น คำสั่งที่ช้าจึงแสดงผลเหมือนกับเมื่อไม่มี ccam เมื่อ Claude Code จบ ccam คำสั่งนั้นก็จะจบด้วย (บน Linux และ macOS รวมถึงทุกโปรเซสที่คำสั่งนั้นเริ่ม)

`ccam statusline install` เขียน `statusLine` ลงใน `settings.json` ของแต่ละบัญชี และคงคีย์อื่นของออบเจ็กต์ไว้ เช่น `padding`, `refreshInterval` และ `hideVimModeIndicator` เมื่อบัญชีมีคำสั่งแถบสถานะอยู่แล้ว ccam จะเก็บไว้เป็น `--wrap '<old command>'` ส่วนบน Windows จะเก็บเป็น `--wrap-base64 <base64>` ซึ่งไม่ต้องใส่เครื่องหมายคำพูดในเชลล์ใดเลย หากแถบสถานะรัน ccam อยู่แล้ว (จากพาธอื่น หรือใส่เครื่องหมายคำพูดแบบที่เวอร์ชันเก่าเขียนไว้) ccam จะแทนที่แทนการครอบ และคงคำสั่งที่แถบสถานะนั้นครอบอยู่ไว้

บน Windows พาธไปยัง ccam จะเขียนด้วยเครื่องหมายทับ (/) และใช้ `~` แทนโฟลเดอร์ home (`~/.local/bin/ccam.exe statusline`) ซึ่งทั้ง Git Bash และ PowerShell เข้าใจ พาธที่ต้องใส่เครื่องหมายคำพูดจะเขียนเต็มสำหรับเชลล์ที่ Claude Code ใช้: `'…'` สำหรับ Git Bash และ `& '…'` สำหรับ PowerShell ส่วน `settings.json` ที่ใช้ร่วมกันผ่านกลุ่มจะถูกเขียนเพียงครั้งเดียวผ่านลิงก์ ทุกบัญชีในกลุ่มจึงได้รับด้วย การรันซ้ำจะพิมพ์ `(already set)` สำหรับไฟล์ที่ใช้ ccam อยู่แล้ว

## ความปลอดภัยและกรณีพิเศษ

- `ccam usage` ไม่เคยเปลี่ยนแปลงไฟล์โทเค็น เว้นแต่คุณจะใส่ `--refresh` เมื่อโทเค็นการเข้าถึงหมดอายุ ให้เริ่มบัญชีนั้นหนึ่งครั้งด้วย `ccam <name>` แล้ว Claude Code จะต่ออายุให้ ส่วนการเข้าสู่ระบบที่หมดอายุทั้งหมดต้องใช้ `ccam login <name>`
- `--refresh` ไม่เคยแตะบัญชีที่กำลังทำงาน (รวมถึงเมื่อ Claude Code ถูกเริ่มโดยไม่ผ่าน ccam) บัญชีที่นำเข้า หรือการเข้าสู่ระบบในพวงกุญแจ (Keychain) การต่ออายุที่ถูกปฏิเสธจะแสดงตัวเลขที่บันทึกไว้พร้อมเหตุผล (`token not renewed: …`)
- endpoint การใช้งานไม่มีเอกสารเผยแพร่สู่สาธารณะและอาจเปลี่ยนแปลงได้ เมื่อเปลี่ยน คุณจะยังเห็นตัวเลขที่บันทึกไว้ และ `ccam doctor` จะรายงานการเปลี่ยนรูปแบบ
- เมื่อไม่มีตัวเลขที่บันทึกไว้และไม่มีคำตอบ บรรทัดของบัญชีจะแสดง `lookup failed:` พร้อมเหตุผล เช่น `no saved usage` เมื่อใช้ `--source cache`
- ไฟล์แคชเก็บเพียงเปอร์เซ็นต์และเวลารีเซ็ต ไม่เคยเก็บโทเค็น
