`ccam next` открывает Claude Code от имени другого аккаунта, не требуя указывать его имя. Используйте его, когда аккаунт достиг лимита использования. Переключиться можно четырьмя способами:

- Обычный `ccam next` берёт аккаунт, следующий за последним использованным, а `--auto` берёт аккаунт с наибольшим запасом. `--continue` продолжает последний разговор этой папки в новом аккаунте, независимо от того, общая ли у них история.
- Внутри Claude Code [плагин ccam](#inside-claude-code) сообщает, когда лимит останавливает сессию, а `/ccam:switch` передаёт разговор дальше.
- Для скриптов, которые запускают `claude -p`, `ccam --fallback` делает переключение сам (см. [Повторный запуск при лимите](#run-again-at-the-limit)).
- При включённом [`auto_switch`](#auto-switch) (Linux и macOS) ccam также переносит интерактивную сессию, которую Claude Code останавливает на её лимите.

**Места в тарифах Team и Enterprise.** Автоматический выбор аккаунта (`ccam next`, `--fallback`, `ccam pick`, клавиша `n` на панели и, если вы его включите, [`auto_switch`](/features/next#auto-switch)) переключается и между местами одной и той же организации Claude Team или Enterprise, что может нарушать условия Anthropic. Прочитайте [FAQ](/docs/faq#am-i-allowed-to-use-several-claude-code-accounts) и уточните это у своей организации и у Anthropic, прежде чем на него полагаться.

## Использование

```sh
ccam next                       # the account after the one you used last
ccam next --auto                # the account with the most room
ccam next --continue            # continue this folder's last conversation on the next account
ccam next -c --auto             # both: the conversation, on the account with the most room
ccam next -c --brief            # a new conversation that starts from a summary of the last one
ccam next --auto --max-usage 80 # prefer accounts below 80%
ccam next --auto --strategy balance   # the most weekly quota left per day
ccam next --auto --cross-org    # also accounts of other organizations
ccam next --auto --wait         # nobody has room: wait for the first reset (up to 5 hours)
ccam next -c --auto -- --dangerously-skip-permissions   # claude's own options go after --
ccam --dry-run next --auto      # print the choice and the command, start nothing
```

```console
$ ccam --dry-run next --auto --continue
→ personal → work (12% of its 5 hours used, the least)
  continuing "Fix the flaky tests" (about 182k tokens); work does not share personal's history, so Claude Code copies it into work
CLAUDE_CONFIG_DIR=/home/you/.local/share/ccam/profiles/work CCAM_PROFILE=work /usr/local/bin/claude --resume /home/you/.local/share/ccam/profiles/personal/projects/-home-you-code-app/4f1c….jsonl --fork-session
```

ccam выводит переключение в виде `→ <from> → <to>` в стандартный поток ошибок, для выбора `--auto` с причиной, а затем запускает Claude Code от имени нового аккаунта так же, как `ccam <name>`. `<from>` означает последний использованный аккаунт, а с `--continue` аккаунт, которому принадлежит разговор. Аргументы после `--` передаются в `claude` без изменений.

## Параметры

| Параметр | Действие | По умолчанию |
| --- | --- | --- |
| `--auto` | Выбрать аккаунт с входом по использованию (см. ниже), пропуская аккаунты со 100% | выкл. |
| `--max-usage <1-100>` | С `--auto`: предпочитать аккаунты ниже этого использования | `auto_max_usage`, иначе 100 |
| `--strategy headroom\|expiring\|balance` | С `--auto`: наименьшее использование за 5 часов, ближайший сброс 5-часового окна или больше всего недельной квоты, оставшейся на день | `auto_strategy`, иначе `headroom` |
| `--cross-org` | С `--auto`: выбирать также аккаунты другой организации (см. ниже) | `cross_org`, иначе выкл. |
| `--wait[=<duration>]` | С `--auto`: если ни у одного аккаунта нет запаса, ждать сброса первого из них, но не дольше этого времени. Значение указывается после `=`: `--wait 2h` отклоняется с подсказкой `--wait takes its value after '=': --wait=2h` | выкл.; `5h`, если указан без значения |
| `-c`, `--continue` | Продолжить последний разговор этой папки в новом аккаунте (см. ниже) | выкл. |
| `--brief` | С `--continue`: начать от имени нового аккаунта новый разговор со сводки последнего, написанной ccam, вместо того чтобы возобновлять его целиком ([см. ниже](#brief)) | выкл. |
| `-- <claude args>` | Аргументы, передаваемые в `claude` после собственных аргументов ccam | нет |
| `--dry-run` | Поддерживается: выводит `→ <from> → <to>` и командную строку, которую выполнил бы, не запуская Claude Code и не записывая запуск | выкл. |

`--auto` и `--continue` можно использовать вместе. С `--continue` аргументы `--resume` ставятся перед вашими.

Собственные опции Claude Code, например `--dangerously-skip-permissions` или `--model`, указываются после `--`. В отличие от `ccam <name>`, который передаёт дальше всё, что идёт после имени, `ccam next` сам разбирает свои аргументы, поэтому без `--` он останавливается с `ccam: unknown flag: --dangerously-skip-permissions`.

## Как это работает

Каждый запуск через ccam записывает время в `~/.local/state/ccam/last-used/<name>`. `ccam next` читает эти файлы, проверяет, в каких аккаунтах выполнен вход, и делает выбор.

1. ccam строит по одному `next.Candidate` на аккаунт из `config.toml` (`cli.candidates`): аккаунт, время его последнего запуска (`launcher.LastUsed`) и наличие рабочего входа (`creds.Has`: вход Claude в `.credentials.json` или, в macOS, в Связке ключей, который не истёк полностью и не был очищен Claude Code). Папка, которая вместо этого использует ключ API (вход через Console или аккаунт, добавленный через `ccam add --api`), не имеет лимитов тарифа и никогда не выбирается.
2. Без `--auto` ccam сортирует аккаунты по номеру слота и находит аккаунт, запущенный последним (`next.Rotate`). С него вы и переключаетесь. Если ни один аккаунт ещё не запускался, это аккаунт с наименьшим слотом.
3. Оттуда он идёт вперёд по порядку слотов, переходя от последнего слота к первому, и возвращает первый аккаунт, в котором выполнен вход.
4. ccam подготавливает и запускает выбранный аккаунт точно так же, как `ccam <name>` (`launcher.LaunchWith`): проверяет ссылки аккаунта, применяет общий доступ к MCP, регистрирует сессию и заменяет ccam на `claude` через `syscall.Exec`.

Обход начинается с последнего использованного аккаунта и останавливается на первом аккаунте с входом после него:

<!-- motion:next-rotate -->

`work` запускался последним, поэтому обход начинается после него. У `side` нет входа, он пропускается, и выбирается `lab`. Если бы из `lab` тоже был выполнен выход, обход вернулся бы к `personal` (`% len` на схеме). Ротация никогда не возвращает аккаунт, с которого она началась: если другого аккаунта с входом нет, она завершается ошибкой.

### --auto

`--auto` выбирает по использованию, а не по порядку слотов. ccam оставляет аккаунты с входом, одновременно запрашивает использование всех этих аккаунтов так же, как `ccam usage` (`Fetcher.FetchAll`), и выбирает по правилам ниже (`cli.pickAuto`, `usage.Policy.Choose()`):

<!-- motion:next-auto -->

Аккаунт оценивается по его 5-часовому и недельному окнам, а если среди аргументов для Claude Code (после `--`) есть `--model`, то и по недельному окну этой модели (`opus`, `sonnet`, `haiku` или `fable` в названии). ccam делит аккаунты на три уровня (`Policy.Choose()`):

1. **Есть запас**: каждое окно ниже `auto_max_usage` (`config.toml`, по умолчанию 100). Среди них выбирает стратегия: `headroom` (по умолчанию) берёт наименьшее использование за 5 часов; `expiring` берёт 5-часовое окно, которое сбросится раньше всех, чтобы его оставшаяся квота была использована, пока не пропала; `balance` берёт аккаунт, у которого больше всего недельной квоты осталось на каждый день до сброса его недели, засчитывая против него каждую запущенную сессию ccam, чтобы недельная квота не оставалась неиспользованной, а параллельные сессии распределялись.
2. **Выше порога**: ниже 100%, но на уровне `auto_max_usage` или выше. Используются, только если ни у одного аккаунта нет запаса; первым идёт аккаунт с наименьшим использованием за 5 часов.
3. **Заполнены**: окно на 100% или неизвестное использование за 5 часов. Никогда не выбираются.

Окно считается заполненным на 100% до своего сброса, если Claude Code отклонил там запрос: это записывает хук [плагина ccam](#inside-claude-code) (`~/.local/state/ccam/usage/<name>.limit.json`), что бы ни говорили сохранённые данные. Поэтому аккаунт, только что достигший лимита, не выбирается снова до сброса, даже если его данные устарели.

Настройки для всех аккаунтов пишутся в начале `config.toml`, над первым `[[group]]`, `[[profile]]` или `[[folder]]`. Настройка под одной из этих таблиц относится к ней: ccam предупреждает о ней при каждом запуске, а команды, которые сохраняют конфигурацию, отказываются работать, пока её не перенесут.

```toml
# ~/.config/ccam/config.toml
auto_max_usage = 80        # keep 20% of each account for interactive work
auto_strategy = "expiring"
```

**Организации.** Автоматический выбор остаётся среди аккаунтов того же вида, что и покидаемый: места в той же организации Team или Enterprise либо личные тарифы (Pro, Max), поэтому работа из рабочего аккаунта не продолжается в личном и наоборот. ccam знает организацию каждого аккаунта по его входу (`ccam login` записывает её; для старых входов она читается из `.claude.json`); аккаунт, организацию которого ccam определить не может, можно сопоставить с любым аккаунтом. Две папки, вошедшие в один и тот же аккаунт Claude, делят его лимиты, поэтому одна никогда не подменяет другую. `--cross-org` или `cross_org = true` в `config.toml` снимает правило организаций, но после [`/ccam:switch`](#inside-claude-code) перенос в другую организацию всё равно ждёт вашего «да».

Когда выбрать нечего, ccam завершается с кодом 75 (`EX_TEMPFAIL`), чтобы скрипт мог отличить «попробуйте позже» от ошибки. С `--wait` он вместо этого ждёт, пока сбросится блокирующее окно первого заполненного аккаунта (через 30 секунд после времени сброса, когда эндпоинт показывает новое окно), выводит `ccam: no account has room; waiting until 15:10` и выбирает снова; если ни один аккаунт не сообщает, когда сбросится, он проверяет снова через 10 минут. Если до конца ожидания ничего не освободится, он завершается с кодом 75.

Запрос подчиняется правилам `ccam usage`: данные моложе 60 секунд используются повторно, запрос для каждого аккаунта прерывается по тайм-ауту через 3 секунды, аккаунт, который не отвечает или чей токен доступа истёк, оценивается по сохранённым данным, а запись о лимите имеет приоритет над ними. Сохранённое окно, время сброса которого прошло, считается за 0%, поэтому аккаунт, окно которого с тех пор сбросилось, не пропускается. `--auto` никогда не обновляет токены. В отличие от обычной ротации, `--auto` может выбрать последний использованный аккаунт, если у него по-прежнему наибольший запас.

### --continue

1. ccam ищет последний разговор этой папки во всех аккаунтах: из файлов `<session>.jsonl` в `projects/<folder>/` (имя папки — это рабочая папка с раскрытыми ссылками, в которой каждый символ, кроме букв и цифр, заменён на `-`, как его называет Claude Code) выбирается тот, где самый новый запрос или ответ. Сессии без них, например сессия, в которой выполнялись только `/mcp`, `/usage` или `/status`, или пустой файл, пропускаются. Если сессия оставила заметку (лимит использования или `/ccam:switch`, см. ниже) и ни в одном разговоре нет запроса или ответа более чем через 2 минуты после неё, используется именно эта сессия; строки, которые Claude Code записывает при `/exit`, не учитываются.
2. Аккаунт, которому он принадлежит, считается тем, с которого вы переключаетесь, а новый аккаунт выбирается, как описано выше, в пределах той же организации. Когда эту историю делят несколько аккаунтов, разговор принадлежит тому, чей `.claude.json` говорит, что он вёл этот разговор последним (`lastSessionId`), а иначе — последнему использованному.
3. Если новый аккаунт делит эту историю (та же папка группы), ccam запускает `claude --resume <session id>`, то есть именно этот разговор (`--continue` открыл бы самый новый разговор в папке, каким бы он ни был).
4. Иначе он запускает `claude --resume <the conversation's file> --fork-session`: Claude Code копирует весь разговор под новым идентификатором сессии в собственную историю нового аккаунта, а оригинал остаётся как был. С этого момента `--continue` нового аккаунта находит его.
5. Если вы не передали `--agent` после `--`, ccam также передаёт агента, от имени которого идёт разговор: настройку `agent` из `.claude/settings.local.json` или `.claude/settings.json` папки или из `settings.json` аккаунта, а иначе агента, которого называет последняя строка `agent-setting` разговора. Claude Code не возвращает агента, когда копирует разговор (шаг 4), и продолжил бы работу как агент по умолчанию, со всеми инструментами. Если новый аккаунт не делит со старым агентов, плагинов и настроек (те же папки `agents` и `plugins` и тот же `settings.json` через группу), ccam добавляет строку после строки о переносе: `work does not share personal's agents, plugins and settings, so it may not have agent "reviewer" or may define it differently: the conversation may go on without that agent's tool limits`.

ccam сообщает размер разговора: новый аккаунт перечитывает его целиком в своём первом ответе. Кэши запросов никогда не делятся между организациями, а каждый личный тариф — это отдельная организация, поэтому, когда два аккаунта принадлежат разным, ccam добавляет `prompt caches are not shared between organizations, so the first reply reads it all again`. Когда старый аккаунт вошёл в MCP-серверы, в которые не вошёл новый, ccam называет их: `work is not signed in to MCP servers that personal is signed in to: linear (sign in with /mcp there; sign-ins are not shared)`. Общая `history` в группе позволяет обойтись без копии, сохраняет один разговор и, кроме того, делает общими контрольные точки, из которых `/rewind` восстанавливает код (`file-history/`).

### --brief

`--continue` возобновляет весь разговор, и новый аккаунт перечитывает его целиком в своём первом ответе. `ccam next --continue --brief` вместо этого начинает новый разговор со сводки старого, которую ccam пишет сам, не обращаясь к модели:

```console
$ ccam next --auto --continue --brief
→ personal → work (12% of its 5 hours used, the least)
  starting a new conversation with ccam's summary of "Fix the flaky tests" instead of resuming it (about 182k tokens)
  summary (6k characters): /home/you/.local/state/ccam/brief/4f1c….md
```

Сводка содержит, в таком порядке и только там, где есть что сказать:

1. название разговора;
2. путь к его расшифровке, чтобы Claude мог найти в ней нужную подробность;
3. ваш первый запрос, если запросов было больше четырёх;
4. сводку, которую Claude Code написал при последнем сжатии разговора;
5. ваши последние четыре запроса, с командами `!` и слэш-командами в том виде, в каком вы их ввели;
6. последний ответ Claude;
7. список задач;
8. 10 файлов, которые Claude изменил последними;
9. `git status --short --branch` папки, до 800 символов.

Список задач хранит не больше 10 пунктов: первыми отбрасываются выполненные, затем самые дальние шаги, так что текущий шаг и следующие за ним остаются. Длинные части обрезаются посередине, а вся сводка укладывается в 16 000 символов.

ccam сохраняет её как `~/.local/state/ccam/brief/<session>.md`, доступный для чтения только вам, а следующий `--brief` удаляет сводки старше 7 дней. Claude Code запускается с одним запросом и прикрепляет упомянутый в нём файл: `Read @"<the summary>", the summary ccam wrote of my earlier Claude Code conversation, which is not loaded here. Then reply with one or two sentences on where the work stands, and wait for my next message.` Запрос, который вы указали после `--`, заменяет последнее предложение (`Then: <your prompt>`), а остальные ваши параметры после `--` идут за ним.

Claude Code заканчивает упоминание на `"` и обрезает его на `#`, поэтому, если в пути к сводке есть один из этих символов, ccam упоминает её по пути относительно рабочей папки; если он есть и в этом пути, запрос называет файл, и Claude читает его своим инструментом Read, который сначала спрашивает разрешения, потому что файл находится вне рабочих папок (при запуске `-p` в режиме Manual Claude Code запрещает чтение, и Claude продолжает без сводки).

`ccam --dry-run next --continue --brief` выводит сводку и ничего не сохраняет. Старый разговор остаётся как был, а новый знает только то, что написано в сводке, поэтому используйте `--brief`, когда задача важнее всех подробностей того, как вы к ней пришли. Без `--continue` ccam останавливается с `--brief works with --continue`; если он не может прочитать разговор или не находит в нём ничего для сводки, он останавливается и сообщает, что `ccam next --continue` без `--brief` возобновит его целиком. [Relay](#relay) и [`auto_switch`](#auto-switch) всегда возобновляют весь разговор. Собственный параметр Claude Code `--brief` указывается после `--`, как и другие его параметры.

## Внутри Claude Code

[Плагин ccam](/docs/install#claude-code-plugin) добавляет два хука (Claude Code 2.1.78 или новее):

- Когда ход останавливается на лимите использования, он записывает разговор и показывает уведомление на рабочем столе в терминалах, которые это поддерживают (iTerm2, WezTerm, Windows Terminal, kitty, Ghostty): ``ccam: work hit its 5-hour limit (resets 3:45pm). `ccam next --continue` continues the conversation on another account.``

  Он знает каждое сообщение, которое Claude Code считает лимитом использования: 5-часовой, недельный, обычный лимит и лимит модели (`You've hit your session limit`, `You've hit your limit`, `You've reached your …` для квоты модели), кредиты использования и лимиты расходов, а также организацию, которая остановила аккаунт.

  Когда Claude Code записал отклонённый запрос в разговор, хук также записывает заполненное окно до его сброса ([запись о лимите](/features/usage#the-limit-record)), кроме остановки, установленной организацией, которую её администраторы могут снять в любой момент. Кратковременное ограничение со стороны сервера или ограничение частоты запросов ключа API не является лимитом использования и не обрабатывается, как и остановка субагента и сессии без участия пользователя (запуски `-p` и фоновые сессии).

  Claude Code 2.1.234 и новее также ждёт в сессии и сам продолжает работу после сброса 5-часового окна; уведомление даёт вам возможность вместо этого переключиться, а при включённом [`auto_switch`](#auto-switch) (Linux и macOS) ccam переключается за вас, если у другого аккаунта есть запас. Если никакой другой аккаунт не может принять разговор, потому что ни один другой аккаунт не принадлежит той же организации Team или Enterprise или ни один не является другим личным тарифом (при включённом `cross_org` подходит любой другой аккаунт Claude), уведомление вместо этого заканчивается на `You have no other personal plans, so ccam cannot move this conversation.` или `You have no other accounts in Acme, so ccam cannot move this conversation.`
- `/ccam:switch [account]` записывает разговор и завершает ход до того, как будет отправлен какой-либо запрос: введите `/exit`, затем выполните `ccam next --continue`, чтобы продолжить разговор в указанном аккаунте (или в следующем). В сессии, где ещё нет разговора, он сообщает, что продолжать нечего. Его запускает только то, что вводите вы: начиная с версии плагина 0.3.2 Claude не может выполнить `/ccam:switch`, а задание, которое планирует Claude (CronCreate, ScheduleWakeup или `.claude/scheduled_tasks.json`), передаёт его Claude как обычный текст.

  Если названный вами аккаунт находится вне организации разговора (место в другой организации Team или Enterprise, личный тариф вместо места или наоборот либо аккаунт с ключом API с любой из сторон), `ccam next --continue` сначала спрашивает, что бы ни говорил `cross_org`: `ccam: /ccam:switch named home, a personal plan, but this conversation is on work, a Claude Team seat in Acme. Move it to home? [y/N]`. То же самое он спрашивает перед аккаунтом, который выбирает сам, если вы ни одного не назвали, и который `cross_org = true` позволяет ему взять из другой организации: `ccam: the account picked for /ccam:switch is home, a personal plan, …`. Переносит разговор только `y` или `yes`; в Linux и macOS клавиши, нажатые до вопроса, сначала отбрасываются. Любой другой ответ или отсутствие терминала, где можно задать вопрос, оставляет разговор и заметку там, где они есть: ``the conversation stays on work, a Claude Team seat in Acme: it moves to home, a personal plan, only when you answer yes on a terminal. `ccam next --continue` asks again, and `ccam work --resume <session id>` continues it as work`` (после выбора `ccam next --continue` выбирает заново). Как и при автоматическом выборе, аккаунт, организацию которого ccam определить не может, подходит к любому.

Заметка хранится в `~/.local/state/ccam/handoff/<account>/<session>.json`, по одному файлу на сессию, поэтому две сессии одного аккаунта никогда не перезаписывают заметки друг друга. Она хранится 12 часов и используется один раз, когда вот-вот начнётся следующая сессия; если запуск не удался, она остаётся для следующей попытки. Она относится к папке, в которой началась сессия, даже после `cd` в оболочке Claude Code. `ccam rename` обновляет имена в ней; если указанный в ней аккаунт с тех пор удалён, ccam сообщает об этом и выбирает как обычно.

### Relay

С `relay = true` в начале `config.toml` ccam продолжает работать рядом с интерактивными сессиями вместо того, чтобы заменять себя на Claude Code, и после `/ccam:switch` сам продолжает разговор этой сессии (заметку, оставленную другой сессией, он не обрабатывает): хук завершает Claude Code, и ccam выполняет `ccam next --continue` с заметкой этой сессии. Если аккаунт не указан, берётся аккаунт с наибольшим запасом с учётом модели разговора, а когда `cross_org = true` позволяет, чтобы это был аккаунт другой организации, ccam задаёт вопрос выше, прежде чем перенести туда разговор. В Windows хук не может завершить Claude Code: введите `/exit`, и ccam продолжит разговор. Не завершает хук Claude Code и для аккаунта вне организации разговора: он сообщает `ccam: type /exit; ccam then asks whether to continue this conversation on home, a personal plan (work is a Claude Team seat in Acme).`, и ccam задаёт вопрос выше, как только вы введёте `/exit`. Это стоит одного ожидающего процесса ccam на сессию, поэтому по умолчанию режим выключен.

Переданная сессия сохраняет то, что не восстанавливает возобновление разговора: параметры вроде `--add-dir`, `--mcp-config`, списков инструментов, `--settings`, `--plugin-dir` и параметров системного запроса, режим разрешений разговора, уровень усилий сессии и агента, от имени которого идёт разговор (см. [`--continue`](#continue)). `--model` и `--name` Claude Code сам восстанавливает из разговора. Всё остальное (`--worktree`, `--debug`, `--remote-control`, параметры, которых ccam не знает) называется в `ccam: not carried over: …`. Переключение никогда не задаёт вопрос об общей истории, а то, что вы ввели во время него, отбрасывается; его единственный вопрос — тот, что задаётся перед аккаунтом другой организации.

Relay продолжает разговор, только когда Claude Code завершился так, как просил `/ccam:switch`: не тогда, когда вы сначала ввели `/exit`, нажали Ctrl+C во время завершения или ccam получил сигнал разрыва связи или другой сигнал, и не тогда, когда терминала больше нет. Тогда заметка остаётся, и `ccam next --continue` продолжит разговор позже. Сессию, запущенную под relay более старой версии ccam, или сессию без участия пользователя (запуски `-p` и фоновые сессии) хук не завершает; вместо этого она получает сообщение про `/exit`. `claude remote-control` работает без relay.

### `auto_switch`

С `auto_switch = true` в начале `config.toml` (Linux и macOS) ccam сам переносит сессию в другой аккаунт, когда Claude Code останавливает её на лимите использования: хук плагина выбирает другой аккаунт с запасом и завершает Claude Code, а ccam, работающий рядом с сессией, продолжает разговор там, так же как [relay](#relay) делает это после `/ccam:switch`. По умолчанию эта функция выключена, и она экспериментальная.

```toml
# ~/.config/ccam/config.toml
auto_switch = true   # Linux and macOS; turns the relay on too
```

```console
ccam: personal hit its 5-hour limit; continuing this conversation as side
→ personal → side
  continuing "Fix the flaky tests" (about 182k tokens); prompt caches are not shared between organizations, so the first reply reads it all again; side does not share personal's history, so Claude Code copies it into side
```

ccam переносит сессию, только если выполнены все эти условия:

1. ccam запустил её в терминале и продолжает работать рядом с ней. `auto_switch` включает [relay](#relay), поэтому это выполняется для интерактивных сессий, которые вы запускаете после включения настройки. Сессия, запущенная раньше или под более старым ccam, получает уведомление, которое заканчивается на ``This session started before auto_switch was on or under an older ccam, so ccam cannot move it: type /exit, then run `ccam next --continue`.`` Сессии без участия пользователя (запуски `-p` и фоновые сессии), `claude remote-control` и Claude Code, запущенный без ccam, никогда не переносятся.
2. У аккаунта включён [плагин ccam](/docs/install#claude-code-plugin), и он работает с Claude Code 2.1.214 или новее, который передаёт хуку идентификатор своего процесса (`CLAUDE_PID`).
3. Claude Code записал в разговор отклонённый запрос со временем сброса для 5-часового, недельного, Opus или Sonnet лимита этого аккаунта. Лимит расходов, исчерпанные кредиты использования, остановка организацией, квота Fable (`You've reached your Fable limit.`), ограничение со стороны сервера, ограничение частоты запросов ключа API и остановка субагента никогда не переносят сессию.
4. ccam знает тариф аккаунта из его `.claude.json` или из того, что записал `ccam login`. Если нет, уведомление заканчивается на `ccam does not know personal's plan, so auto_switch leaves this session.`
5. Сессия не подключена к Remote Control. От имени другого аккаунта она не подключилась бы снова к приложению, из которого вы ею управляете, поэтому она остаётся, и уведомление об этом сообщает.
6. Лимит сбрасывается более чем через 15 минут. При более коротком ожидании ccam оставляет сессию Claude Code: `ccam: personal hit its 5-hour limit, which resets in 9m; ccam leaves this session to wait for it.`
7. После лимита вы не вводили запрос.
8. У другого аккаунта есть запас. ccam выбирает так же, как [`--auto`](#auto) (`auto_max_usage`, `auto_strategy`, модель разговора), среди аккаунтов того же вида, что и покидаемый: другого места той же организации Team или Enterprise или другого личного тарифа (Pro, Max). `cross_org` и `--cross-org` здесь не действуют. Аккаунт должен:
   - быть с входом, который Claude Code может обновить;
   - не быть входом в тот же аккаунт Claude;
   - не использовать ключ API;
   - иметь известный ccam тариф;
   - не иметь включённых кредитов использования, насколько это видно из собственного запроса использования ccam;
   - доверять этой папке в Claude Code;
   - если разговор идёт от имени агента (его называет настройка `agent` или сам разговор), делить агентов с аккаунтом, который вы покидаете: его папки `agents` и `plugins` и его `settings.json` должны — каждый по отдельности — быть в точности теми же самыми (через группу) или отсутствовать в обоих аккаунтах.

   Если из-за трёх последних условий исключаются все аккаунты с запасом, уведомление их называет: `side has not trusted this folder yet, so the conversation was not moved there. Open the folder once as side to allow it.`, `side has room but its usage credits are on, so auto_switch did not move the conversation there; /ccam:switch side moves it.` или `This conversation runs as agent "reviewer", and side does not share personal's agents, plugins and settings, so auto_switch did not move it there.` Окно с [записью о лимите](/features/usage#the-limit-record) считается заполненным, а аккаунт, в который другая сессия перешла за последние 2 минуты, идёт после остальных. Выбор должен быть сделан примерно за 6 секунд; если запросы использования занимают больше времени, сессия остаётся. С `usage_source = "claude"` `auto_switch` решает только по сохранённым данным, а ccam не может узнать ни из запроса Claude Code, ни из строки состояния, включены ли кредиты использования, поэтому считает их выключенными.

Затем хук завершает Claude Code, а ccam, работающий рядом с ним, показывает уведомление на рабочем столе в терминалах, которые это поддерживают, например `ccam: personal hit its 5-hour limit (resets 3:29am). Moving this conversation to side (12% of its 5 hours used, the least).` Он выводит первую строку примера вывода выше и выполняет для этой сессии `ccam next --continue` от имени выбранного аккаунта; эта команда выводит свои две другие строки и запускает Claude Code с параметрами сессии, режимом разрешений, уровнем усилий и агентом, как это делает [relay](#relay). Первое сообщение новой сессии — этот фиксированный текст, единственное, что ccam отправляет от вашего имени (перенос после `/ccam:switch` ничего не отправляет):

```text
Your usage limit was reached and ccam moved this conversation to another account. Continue the task you were working on when the limit was reached; do not repeat work that is already complete.
```

Если и этот аккаунт достигнет лимита, там произойдёт то же самое. Записи о лимите не дают цепочке вернуться к аккаунту до его сброса, поэтому, когда заполнены все аккаунты, сессия остаётся на последнем.

О том, что разговор идёт от имени агента, хук узнаёт из настройки `agent` или из строки с именем агента, которую Claude Code время от времени и при завершении сессии записывает в разговор. Если пока агента называет только `--agent` сессии, а выбранный аккаунт не делит агентов, `ccam next --continue` ничего не запускает и сохраняет заметку, а второе уведомление на рабочем столе сообщает об этом: ``ccam: this conversation runs as agent "reviewer", and side does not share personal's agents, plugins and settings, so ccam did not move it there. Its note stays: `ccam next --continue` continues it later, and `ccam personal --resume <session id>` continues it as personal after the reset``.

Если ни у одного другого аккаунта нет запаса, ничего не переносится: Claude Code обрабатывает лимит как обычно, ожидая в сессии или предлагая свои варианты, а уведомление сообщает, какой аккаунт освободится первым, например `ccam: personal hit its 5-hour limit (resets 3:29am). None of your other personal plans has room now; side frees up first, at 12:30am. Claude Code waits for personal here; /ccam:switch side after 12:30am moves it sooner.` Для мест оно говорит `None of your other accounts in Acme has room now`. Чтобы остановить уже начавшийся перенос, нажмите Ctrl+C, пока Claude Code закрывается: ``ccam: switch cancelled. Run `ccam next --continue` later to continue the conversation.``

У переноса есть издержки. Claude Code перезапускается, что занимает несколько секунд, а фоновые оболочки, серверы разработки и агенты, которые запустил Claude, останавливаются вместе со старой сессией. Новый аккаунт перечитывает весь разговор в своём первом ответе, как и при [`--continue`](#continue), и ccam сообщает его размер; перенос никогда не использует [`--brief`](#brief).

`auto_switch` никогда не переключается до того, как Claude Code сообщит о лимите, никогда не следит за вашим использованием в фоне и никогда не копирует, не обновляет и не передаёт данные входа. В Windows он игнорируется, и `ccam doctor` об этом сообщает; там с `relay = true` `/ccam:switch` и `/exit` по-прежнему переносят разговор в другой аккаунт.

**Условия Anthropic.** На местах Team и Enterprise `auto_switch` переносит вашу работу на другое место той же организации. В справочном центре Anthropic ([тарифы Team](https://support.claude.com/en/articles/12004354-purchase-and-manage-seats-on-team-plans#h_b8a7d07129); аналогично для [тарифов Enterprise](https://support.claude.com/en/articles/13393991-purchase-and-manage-seats-on-enterprise-plans#h_fa6b9cade0)) сказано: «Each seat on a Team plan is assigned to one named individual, and only that person may use it» (каждое место в тарифе Team закреплено за одним конкретным человеком, и пользоваться им может только этот человек) и «Users can't route their work through another user's account to use that user's remaining usage» (пользователи не могут направлять свою работу через аккаунт другого пользователя, чтобы расходовать оставшийся лимит этого пользователя).

Для личных тарифов (Pro, Max) условия Anthropic не говорят, могут ли ваши собственные аккаунты автоматически подменять друг друга на лимите. [Consumer Terms](https://www.anthropic.com/legal/consumer-terms) запрещают доступ к сервисам «through automated or non-human means, whether through a bot, script, or otherwise» (автоматизированными или нечеловеческими средствами, будь то бот, скрипт или иное), если Anthropic явно это не разрешает, а перенос отправляет от вашего имени фиксированное сообщение, приведённое выше. [Usage Policy](https://www.anthropic.com/legal/aup), которая вступает в силу 12 ноября 2026 года, относит к запрещённому «Intentionally bypass or interfere with capabilities, restrictions, or guardrails established within our products» (намеренно обходить возможности, ограничения или защитные механизмы, установленные в продуктах, или вмешиваться в них).

ccam не утверждает, что `auto_switch` соответствует этим условиям. Включать ли его, решать вам, и риск тоже ваш: Anthropic может заблокировать аккаунт или доступ организации Team или Enterprise, если сочтёт, что условия нарушены.

Пока `auto_switch` включён, `ccam doctor` предупреждает об аккаунте без плагина ccam и о версиях Claude Code старше 2.1.214, а для мест повторяет правило Anthropic о местах ([проверки](/features/doctor)).

## Повторный запуск при лимите

`ccam next` предназначен для остановившейся интерактивной сессии. Неинтерактивный запуск, `claude -p` в скрипте или задании по расписанию, не может ждать вас, поэтому `--fallback` перед именем аккаунта позволяет ccam переключиться за него:

```sh
ccam --fallback work -p "fix the failing tests" --output-format json
ccam --fallback -p "summarise" < notes.txt      # the folder's account or the default
ccam run --fallback work -p "review the diff"
```

```console
$ ccam --fallback personal -p "summarise" < notes.txt
ccam: personal reached its usage limit; running the command again as work
Summary: …
```

1. `--fallback` работает только вместе с `-p` или `--print`; иначе ccam останавливается и указывает на `ccam next --auto --continue`.
2. Стандартный ввод из канала читается один раз, до 10 МиБ, и передаётся каждой попытке. Как и Claude Code, ccam ждёт его начала не более 3 секунд (кроме случая с `--input-format stream-json`); если канал остаётся открытым, но ничего не передаёт, запуск получает пустой ввод, и ccam сообщает об этом в стандартном потоке ошибок.
3. ccam запускает `claude` как дочерний процесс вместо `exec`, придерживает его стандартный вывод и передаёт стандартный поток ошибок по мере поступления.
4. Когда `claude` завершается с кодом 0 или с ошибкой по другой причине, придержанный вывод и код возврата передаются без изменений. Так же обрабатывается запуск, завершённый сигналом (код возврата больше 128): его попросили остановиться, и он не запускается снова.
5. Ошибка считается достижением лимита использования, когда об этом говорит сообщение Claude Code — любое из сообщений о лимите использования, которые знает [хук](#inside-claude-code), в том числе внутри вывода `--output-format json` или `stream-json`, — или когда использование аккаунта показывает его 5-часовое, недельное окно или окно `--model` на 100% (включая запись о лимите).
6. Тогда вывод этой попытки отбрасывается, и та же команда запускается от имени другого аккаунта с входом: сначала с наименьшим использованием за 5 часов, затем аккаунты, использование которых узнать не удалось, в порядке номеров. Аккаунты на 100% пропускаются, аккаунты со входом по ключу API никогда не пробуются, и каждый аккаунт пробуется не более одного раза.
7. Если среди аргументов есть `-c`, `--continue`, `-r` или `--resume`, пробуются только аккаунты из той же группы истории, чтобы разговор можно было найти.
8. Пробуются только аккаунты той же организации, как и с `--auto` (`cross_org = true` снимает это ограничение).

Следующий аккаунт выбирается по тем же правилам, что и в `--auto` (`auto_max_usage`, `auto_strategy`, окно `--model`). Когда аккаунтов не осталось, ccam выводит результат последней попытки, сообщает, что ни у одного аккаунта с входом не осталось запаса, и завершается с кодом 75. С `--wait` перед именем аккаунта (`ccam --fallback --wait=2h work -p …`) он вместо этого ждёт сброса первого аккаунта, после чего может снова попробовать все аккаунты; сначала он всегда хотя бы раз ждёт, чтобы аккаунт, только что достигший лимита, не запускался снова сразу же. Длительность ограничивает общее время ожидания запуска, а не каждое ожидание. Если записать её через пробел (`--wait 30m`), она отклоняется с той же подсказкой, что и в `ccam next`. Начальный `--` перед аргументами Claude Code работает так же, как при любом запуске (`ccam --fallback work -- -p …`). `ccam --dry-run --fallback work -p …` выводит команду первой попытки.

Интерактивные сессии сами не переключаются, если вы не включили [`auto_switch`](#auto-switch). С `ccam statusline install` строка состояния добавляет `→ ccam next --auto --continue`, как только использование за 5 часов или за неделю доходит до 90% ([Лимиты использования](/features/usage)).

## Безопасность и особые случаи

- Аккаунты без входа никогда не выбираются. Если другого аккаунта с входом нет, обычный `ccam next` завершается с сообщением `no logged-in account other than <name>`.
- С `--continue`, если в папке нет разговора: `no account has a conversation in <folder> to continue`.
- Если после правила организаций не остаётся ни одного аккаунта: `` no logged-in account to pick among <name>'s (<organization>); --cross-org also looks at the others ``.
- С `--auto`, если нет ни одного аккаунта с входом: `no logged-in account to pick`. Если каждый аккаунт заполнен или его использование неизвестно: `` no account with known usage and headroom (see `ccam usage`) ``. В обоих случаях код выхода 75.
- `--max-usage`, `--strategy`, `--wait` и `--cross-org` работают только с `--auto`, а значение вне диапазона 1-100 или неизвестная стратегия отклоняются.
- Ответвление копирует разговор, но не остальное состояние аккаунта: контрольные точки из `file-history/` исходного аккаунта не переносятся, если история не общая.
- `--auto` выполняет сетевые запросы даже с `--dry-run`. Он только читает и никогда не записывает файлы токенов.
- Выбранный аккаунт запускается тем же путём, что и `ccam <name>`, поэтому действуют те же проверки, включая предупреждение, когда в этой папке уже работает другая сессия Claude Code с той же историей.
- `last-used` записывается, только когда Claude Code действительно запускается. `--dry-run` его не трогает, поэтому пробный запуск не сдвигает ротацию.
- `--fallback` придерживает стандартный вывод до конца попытки, поэтому потоковый вывод, например `--output-format stream-json`, приходит одним куском в конце. Клиент, который передаёт ввод `stream-json` потоком и ждёт ответов, прежде чем отправить ещё, не может использовать `--fallback`. Файлы, которые первая попытка изменила до достижения лимита, остаются изменёнными; следующая попытка начинает запрос заново.
