Собственные субагенты Claude Code работают от имени аккаунта сессии, которая их запускает, поэтому расходуют лимит этого аккаунта. `ccam agent "<task>"` выполняет задачу через `claude -p` в той же папке от имени другого вашего аккаунта и выводит последний ответ Claude. Вызванный из сессии Claude Code, он работает как субагент, расходующий лимит другого аккаунта, поэтому одна длинная задача может продолжаться и после того, как собственный аккаунт сессии исчерпал бы свой лимит.

**Места в тарифах Team и Enterprise.** `ccam agent` выбирает аккаунт сам. В пределах одной организации Claude Team или Enterprise он выполняет задачу на другом месте, что может нарушать условия Anthropic. Прочитайте [FAQ](/docs/faq#am-i-allowed-to-use-several-claude-code-accounts) и уточните это у своей организации и у Anthropic, прежде чем на него полагаться.

## Использование

Claude Code запускает его своим инструментом Bash. Если установлен [плагин ccam](/docs/install#claude-code-plugin), попросите об этом простыми словами, например «используй мои другие аккаунты для частей этой задачи», или напишите это в своём CLAUDE.md. Навык плагина велит Claude Code запускать каждого агента в фоне, писать задачу, понятную без остального контекста, и давать агентам, которые редактируют файлы, свою часть работы или свой git worktree.

```sh
ccam agent "find why TestParse fails and fix it; reply with what you changed"
ccam agent --model opus -- "-v breaks the parser: find out why"
ccam agent --json < task.md            # the task from standard input
ccam agent --resume 7f3c9a2e-… "now add a test for it"
ccam agent --wait=1h "…"               # nobody has room: wait for a reset
ccam --dry-run agent "…"               # the account and command it would run
```

```console
$ ccam agent "summarize what internal/usage does"
ccam: agent runs as work (12% of its 5 hours used); session 7f3c9a2e-5b1d-4c2a-9e8f-1a2b3c4d5e6f
internal/usage looks up the 5-hour and weekly usage of every account …
ccam: agent finished as work; follow up with: ccam agent --resume 7f3c9a2e-5b1d-4c2a-9e8f-1a2b3c4d5e6f "…"
```

Последний ответ Claude идёт в стандартный вывод; строки, начинающиеся с `ccam:`, идут в стандартный поток ошибок. `--json` вместо этого выводит `{account, session_id, result, is_error, accounts}`, где `accounts` перечисляет все аккаунты, от имени которых выполнялась задача.

Коды выхода: собственный код claude (`0`, когда агент завершил работу), `75` (`EX_TEMPFAIL`), когда ни у одного аккаунта, кроме вызывающего, нет запаса, `1` для других ошибок, например когда агент пытается запустить другого агента.

## Параметры

| Параметр | Действие | По умолчанию |
| --- | --- | --- |
| `--model <model>` | Модель агента; при выборе учитывается и недельное окно этой модели | модель аккаунта по умолчанию |
| `--resume <id>` | Продолжить разговор прежнего агента со следующей задачей (идентификатор сессии в его первой и последней строке) | выкл. |
| `--json` | Вывести аккаунт, сессию, ответ и аккаунты, от имени которых он работал | выкл. |
| `--max-usage <1-100>` | Предпочитать аккаунты ниже этого использования | `auto_max_usage`, иначе 100 |
| `--strategy headroom\|expiring\|balance` | [Правило выбора](/features/next#auto) | `auto_strategy`, иначе `headroom` |
| `--cross-org` | Работать также от имени аккаунтов других организаций | `cross_org`, иначе выкл. |
| `--wait[=<duration>]` | Если ни у одного аккаунта нет запаса, ждать сброса первого из них, но не дольше этого времени | выкл.; `5h`, если указан без значения |
| `--dry-run` | Вывести команду для аккаунта, который был бы выбран, не запуская её | выкл. |

## Как это работает

1. **Вызывающий аккаунт не участвует.** Аккаунт, из которого вызван `ccam agent` (аккаунт сессии, запущенной ccam, иначе тот, который запускает эта папка), никогда не выполняет агента; не выполняет его и другая папка, вошедшая в тот же аккаунт Claude, поскольку у них общие лимиты. Агент остаётся в [организации](/features/next#auto) вызывающего аккаунта, если `--cross-org` не указывает иное.
2. **Он выбирает так же, как `ccam pick`.** Использование запрашивается так же, как это делает [`ccam pick`](/features/pick), а агенты, запущенные в пределах 2 минут друг от друга, получают разные аккаунты, пока аккаунтов с запасом достаточно.
3. **Он работает с разрешениями сессии, но не больше.** В `claude -p` некому разрешить инструмент, поэтому агент получает режим разрешений и уровень усилий вызвавшей его сессии. При запуске из терминала действуют режим Claude Code по умолчанию и правила разрешений из ваших настроек. У `ccam agent` нет параметра, который давал бы больше.
4. **При лимите использования разговор продолжается.** Когда аккаунт агента достигает лимита, ccam записывает лимит так, как это сделал бы [хук плагина](/features/usage#the-limit-record), и продолжает тот же разговор от имени аккаунта с наибольшим запасом: Claude Code копирует его туда (`--resume <file> --fork-session`) с первым сообщением «Your usage limit was reached and ccam moved this conversation to another account. Continue the task you were working on when the limit was reached; do not repeat work that is already complete.» Каждый аккаунт пробуется один раз.
5. **Каждый разговор агента записывается** в `~/.local/state/ccam/agent/<session id>.json` (30 дней). `--resume <id>` продолжает его в его папке от имени аккаунта, который его вёл, если у того ещё есть запас, иначе от имени другого. [`ccam next --continue`](/features/next) не учитывает разговоры агентов, поэтому продолжает именно ваши.

## Безопасность и особые случаи

- Агент не может запускать собственных агентов: ccam помечает его через `CCAM_AGENT=1`, и `ccam agent` там отказывается работать.
- Остановка `ccam agent` (Ctrl+C, сигнал или прерывание команды со стороны Claude Code) останавливает и агента.
- Агент не видит разговор, из которого его вызвали, только свою задачу.
- Агенты, одновременно редактирующие одни и те же файлы, перезаписывают работу друг друга. Дайте каждому свою часть задачи или свой git worktree.
- Когда вызывающая сессия переходит на другой аккаунт ([`auto_switch`](/features/next#auto-switch)), запущенные ею агенты останавливаются вместе с ней. Их разговоры сохраняются: `--resume <id>` продолжает их.
- `agent` — имя команды, поэтому ни один новый аккаунт не может называться `agent`; существующий по-прежнему запускается через `ccam run agent`.
