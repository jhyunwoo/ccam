Власні субагенти Claude Code працюють від імені облікового запису сеансу, який їх запускає, тож витрачають ліміт саме цього облікового запису. `ccam agent "<task>"` виконує завдання через `claude -p` у тій самій теці від імені іншого вашого облікового запису й виводить останню відповідь Claude. Коли його викликають із сеансу Claude Code, він працює як субагент, що витрачає ліміт іншого облікового запису, тож одне довге завдання може тривати й тоді, коли власний обліковий запис сеансу вже вичерпав би свій ліміт.

**Місця в планах Team і Enterprise.** `ccam agent` сам вибирає обліковий запис. У межах однієї організації Claude Team або Enterprise він виконує завдання на іншому місці, що може порушувати умови Anthropic. Прочитайте [FAQ](/docs/faq#am-i-allowed-to-use-several-claude-code-accounts) і уточніть це у своїй організації та в Anthropic, перш ніж на нього покладатися.

## Використання

Claude Code запускає його через свій інструмент Bash. Коли встановлено [плагін ccam](/docs/install#claude-code-plugin), попросіть про це звичайними словами, наприклад «використай мої інші облікові записи для частин цього завдання», або запишіть це у свій CLAUDE.md. Навичка плагіна каже Claude Code запускати кожного агента у фоні, писати завдання, зрозуміле без додаткового контексту, і давати агентам, що редагують файли, власну частину або власний git worktree.

```sh
ccam agent "find why TestParse fails and fix it; reply with what you changed"
ccam agent --model opus -- "-v breaks the parser: find out why"
ccam agent --json < task.md            # the task from standard input
ccam agent --resume 7f3c9a2e-… "now add a test for it"
ccam agent --wait=1h "…"               # nobody has room: wait for a reset
ccam --dry-run agent "…"               # the account and command it would run
```

```console
$ ccam agent "summarize what internal/usage does"
ccam: agent runs as work (12% of its 5 hours used); session 7f3c9a2e-5b1d-4c2a-9e8f-1a2b3c4d5e6f
internal/usage looks up the 5-hour and weekly usage of every account …
ccam: agent finished as work; follow up with: ccam agent --resume 7f3c9a2e-5b1d-4c2a-9e8f-1a2b3c4d5e6f "…"
```

Остання відповідь Claude йде у стандартний вивід; рядки, що починаються з `ccam:`, ідуть у стандартний потік помилок. `--json` натомість виводить `{account, session_id, result, is_error, accounts}`, де `accounts` перелічує всі облікові записи, від імені яких виконувалося завдання.

Коди виходу: власний код claude (`0`, коли агент завершив роботу), `75` (`EX_TEMPFAIL`), коли жоден обліковий запис, крім того, з якого викликано, не має запасу, `1` для інших помилок, як-от спроби агента запустити іншого агента.

## Параметри

| Параметр | Дія | За замовчуванням |
| --- | --- | --- |
| `--model <model>` | Модель агента; тижневе вікно цієї моделі теж враховується під час вибору | модель облікового запису за замовчуванням |
| `--resume <id>` | Продовжити розмову попереднього агента з наступним завданням (ідентифікатор сеансу в його першому й останньому рядку) | вимкнено |
| `--json` | Вивести обліковий запис, сеанс, відповідь і облікові записи, від імені яких виконувалося завдання | вимкнено |
| `--max-usage <1-100>` | Віддавати перевагу обліковим записам нижче цього використання | `auto_max_usage`, інакше 100 |
| `--strategy headroom\|expiring\|balance` | [Правило вибору](/features/next#auto) | `auto_strategy`, інакше `headroom` |
| `--cross-org` | Виконувати також від імені облікових записів інших організацій | `cross_org`, інакше вимкнено |
| `--wait[=<duration>]` | Коли в жодного облікового запису немає запасу, чекати на скидання першого з них, але не довше за цей час | вимкнено; `5h`, якщо вказано без значення |
| `--dry-run` | Вивести команду для облікового запису, який було б вибрано, не виконуючи її | вимкнено |

## Як це працює

1. **Обліковий запис, що викликає, не враховується.** Обліковий запис, з якого викликано `ccam agent` (обліковий запис сеансу, запущеного ccam, інакше той, що запускається в цій теці), ніколи не виконує агента, як і інша тека, у якій виконано вхід у той самий обліковий запис Claude і яка ділить із ним ліміти. Агент лишається в [організації](/features/next#auto) облікового запису, що викликає, якщо `--cross-org` не вказує інакше.
2. **Він вибирає так само, як `ccam pick`.** Використання з'ясовується так само, як це робить [`ccam pick`](/features/pick), а агенти, запущені з інтервалом до 2 хвилин, отримують різні облікові записи, доки достатньо облікових записів мають запас.
3. **Він працює з дозволами сеансу, ніколи не ширшими.** У `claude -p` немає нікого, хто дозволив би інструмент, тож агент отримує режим дозволів і рівень зусиль сеансу, що його викликав. Під час запуску з термінала діють режим Claude Code за замовчуванням і правила дозволів із ваших налаштувань. `ccam agent` не має параметра, що надає більше.
4. **На ліміті використання розмова продовжується.** Коли обліковий запис агента досягає ліміту, ccam записує ліміт так, як це зробив би [хук плагіна](/features/usage#the-limit-record), і продовжує ту саму розмову від імені облікового запису з найбільшим запасом: Claude Code копіює її туди (`--resume <file> --fork-session`) з першим повідомленням «Your usage limit was reached and ccam moved this conversation to another account. Continue the task you were working on when the limit was reached; do not repeat work that is already complete.» Кожен обліковий запис пробується один раз.
5. **Кожна розмова агента записується** в `~/.local/state/ccam/agent/<session id>.json` (30 днів). `--resume <id>` продовжує її в її теці від імені облікового запису, який її виконував, якщо в нього ще є запас, інакше від імені іншого. [`ccam next --continue`](/features/next) не враховує розмов агентів, тож і далі продовжує ваші.

## Безпека та граничні випадки

- Агент не може запускати власних агентів: ccam позначає його `CCAM_AGENT=1`, і `ccam agent` там відмовляється працювати.
- Зупинка `ccam agent` (Ctrl+C, сигнал або переривання команди з боку Claude Code) зупиняє й агента.
- Агент не бачить розмови, з якої його викликано, лише своє завдання.
- Агенти, що одночасно редагують ті самі файли, перезаписують роботу одне одного. Дайте кожному власну частину завдання або власний git worktree.
- Коли сеанс, що викликав агентів, переходить на інший обліковий запис ([`auto_switch`](/features/next#auto-switch)), запущені ним агенти зупиняються разом із ним. Їхні розмови лишаються: `--resume <id>` продовжує їх.
- `agent` — назва команди, тож жоден новий обліковий запис не може називатися `agent`; наявний обліковий запис із цією назвою й далі запускається через `ccam run agent`.
