Claude Code کے اپنے subagents اسی سیشن کے اکاؤنٹ کے طور پر چلتے ہیں جو انہیں شروع کرتا ہے، اس لیے وہ اسی اکاؤنٹ کا استعمال خرچ کرتے ہیں۔ `ccam agent "<task>"` اسی فولڈر میں `claude -p` کے ساتھ کوئی کام آپ کے کسی دوسرے اکاؤنٹ کے طور پر چلاتا ہے اور Claude کا آخری جواب پرنٹ کرتا ہے۔ Claude Code سیشن سے بلایا جائے تو یہ ایک ایسے subagent کی طرح کام کرتا ہے جو کسی دوسرے اکاؤنٹ کا استعمال خرچ کرتا ہے، اس لیے ایک لمبا کام اس وقت کے بعد بھی جاری رہ سکتا ہے جب سیشن کے اپنے اکاؤنٹ کی گنجائش ختم ہو چکی ہوتی۔

**Team اور Enterprise سیٹیں۔** `ccam agent` اکاؤنٹ خود چنتا ہے۔ ایک ہی Claude Team یا Enterprise تنظیم کے اندر یہ کام کسی دوسری سیٹ پر چلاتا ہے، جس سے Anthropic کی شرائط کی خلاف ورزی ہو سکتی ہے۔ اس پر انحصار کرنے سے پہلے [عام سوالات](/docs/faq#am-i-allowed-to-use-several-claude-code-accounts) پڑھیں اور اپنی تنظیم اور Anthropic سے تصدیق کر لیں۔

## استعمال

Claude Code اسے اپنے Bash ٹول کے ذریعے چلاتا ہے۔ [ccam پلگ اِن](/docs/install#claude-code-plugin) انسٹال ہو تو اسے سادہ الفاظ میں مانگیں، مثلاً "اس کام کے حصوں کے لیے میرے دوسرے اکاؤنٹس استعمال کرو"، یا یہ بات اپنی CLAUDE.md میں لکھ دیں۔ پلگ اِن کی اسکل Claude Code کو بتاتی ہے کہ ہر ایجنٹ کو بیک گراؤنڈ میں شروع کرے، ایسا کام لکھے جو اپنے آپ میں مکمل ہو، اور فائلیں بدلنے والے ایجنٹس کو ان کا اپنا حصہ یا اپنا git worktree دے۔

```sh
ccam agent "find why TestParse fails and fix it; reply with what you changed"
ccam agent --model opus -- "-v breaks the parser: find out why"
ccam agent --json < task.md            # the task from standard input
ccam agent --resume 7f3c9a2e-… "now add a test for it"
ccam agent --wait=1h "…"               # nobody has room: wait for a reset
ccam --dry-run agent "…"               # the account and command it would run
```

```console
$ ccam agent "summarize what internal/usage does"
ccam: agent runs as work (12% of its 5 hours used); session 7f3c9a2e-5b1d-4c2a-9e8f-1a2b3c4d5e6f
internal/usage looks up the 5-hour and weekly usage of every account …
ccam: agent finished as work; follow up with: ccam agent --resume 7f3c9a2e-5b1d-4c2a-9e8f-1a2b3c4d5e6f "…"
```

Claude کا آخری جواب اسٹینڈرڈ آؤٹ پٹ پر جاتا ہے؛ جو لائنیں `ccam:` سے شروع ہوتی ہیں وہ اسٹینڈرڈ ایرر پر جاتی ہیں۔ `--json` اس کے بجائے `{account, session_id, result, is_error, accounts}` پرنٹ کرتا ہے، جہاں `accounts` ان تمام اکاؤنٹس کی فہرست ہے جن کے طور پر کام چلا۔

ایگزٹ کوڈز: claude کا اپنا کوڈ (ایجنٹ مکمل ہو تو `0`)، جب بلانے والے کے سوا کسی اکاؤنٹ میں گنجائش نہ ہو تو `75` (`EX_TEMPFAIL`)، اور دوسری غلطیوں، جیسے کسی ایجنٹ کی دوسرا ایجنٹ شروع کرنے کی کوشش، کے لیے `1`۔

## آپشنز

| آپشن | کیا کرتا ہے | ڈیفالٹ |
| --- | --- | --- |
| `--model <model>` | ایجنٹ کا ماڈل؛ انتخاب میں اس ماڈل کی ہفتہ وار ونڈو بھی شمار ہوتی ہے | اکاؤنٹ کا ڈیفالٹ ماڈل |
| `--resume <id>` | کسی پچھلے ایجنٹ کی گفتگو کو ایک اگلے کام کے ساتھ جاری رکھتا ہے (اس کی پہلی اور آخری لائن پر سیشن id) | بند |
| `--json` | اکاؤنٹ، سیشن، جواب اور وہ اکاؤنٹس پرنٹ کرتا ہے جن کے طور پر کام چلا | بند |
| `--max-usage <1-100>` | اس استعمال سے کم والے اکاؤنٹس کو ترجیح دیتا ہے | `auto_max_usage`، ورنہ 100 |
| `--strategy headroom\|expiring\|balance` | [انتخاب کا اصول](/features/next#auto) | `auto_strategy`، ورنہ `headroom` |
| `--cross-org` | دوسری تنظیموں کے اکاؤنٹس کے طور پر بھی چلاتا ہے | `cross_org`، ورنہ بند |
| `--wait[=<duration>]` | جب کسی اکاؤنٹ میں گنجائش نہ ہو تو پہلے اکاؤنٹ کے ری سیٹ ہونے کا انتظار کرتا ہے، زیادہ سے زیادہ اتنی دیر | بند؛ اکیلا دیا جائے تو `5h` |
| `--dry-run` | جو اکاؤنٹ یہ چنے گا اس کے لیے کمانڈ پرنٹ کرتا ہے، اسے چلائے بغیر | بند |

## یہ کیسے کام کرتا ہے

1. **بلانے والا شامل نہیں ہوتا۔** جس اکاؤنٹ سے `ccam agent` بلایا جاتا ہے (ccam کے شروع کیے گئے سیشن کا اکاؤنٹ، ورنہ وہ جو یہ فولڈر شروع کرتا ہے) وہ کبھی ایجنٹ نہیں چلاتا، اور نہ ہی اسی Claude اکاؤنٹ میں لاگ اِن کوئی دوسرا فولڈر، جو اس کی حدیں شیئر کرتا ہے۔ جب تک `--cross-org` کچھ اور نہ کہے، ایجنٹ بلانے والے کی [تنظیم](/features/next#auto) میں رہتا ہے۔
2. **یہ `ccam pick` کی طرح چنتا ہے۔** استعمال اسی طرح معلوم کیا جاتا ہے جیسے [`ccam pick`](/features/pick) کرتا ہے، اور ایک دوسرے سے 2 منٹ کے اندر شروع ہونے والے ایجنٹس کو الگ اکاؤنٹس ملتے ہیں جب تک کافی اکاؤنٹس میں گنجائش ہو۔
3. **یہ سیشن کی اجازتوں کے ساتھ چلتا ہے، کبھی زیادہ نہیں۔** `claude -p` میں کسی ٹول کی اجازت دینے کے لیے کوئی موجود نہیں ہوتا، اس لیے ایجنٹ کو اسے بلانے والے سیشن کا اجازتوں کا موڈ اور effort ملتا ہے۔ ٹرمینل سے چلایا جائے تو Claude Code کا ڈیفالٹ موڈ اور آپ کی سیٹنگز کے اجازت کے اصول لاگو ہوتے ہیں۔ `ccam agent` کا کوئی ایسا آپشن نہیں جو اس سے زیادہ اجازت دے۔
4. **استعمال کی حد پر گفتگو آگے بڑھتی ہے۔** جب ایجنٹ کا اکاؤنٹ اپنی حد کو پہنچتا ہے تو ccam حد کو اسی طرح ریکارڈ کرتا ہے جیسے [پلگ اِن کا ہُک](/features/usage#the-limit-record) کرتا، اور وہی گفتگو سب سے زیادہ گنجائش والے اکاؤنٹ کے طور پر جاری رکھتا ہے: Claude Code اسے وہاں کاپی کرتا ہے (`--resume <file> --fork-session`)، اور پہلا پیغام یہ ہوتا ہے: "Your usage limit was reached and ccam moved this conversation to another account. Continue the task you were working on when the limit was reached; do not repeat work that is already complete." ہر اکاؤنٹ ایک بار آزمایا جاتا ہے۔
5. **ہر ایجنٹ گفتگو ریکارڈ ہوتی ہے** `~/.local/state/ccam/agent/<session id>.json` میں (30 دن)۔ `--resume <id>` اسے اس کے فولڈر میں جاری رکھتا ہے، اسی اکاؤنٹ کے طور پر جس نے اسے چلایا تھا اگر اس میں ابھی گنجائش ہو، ورنہ کسی دوسرے کے طور پر۔ [`ccam next --continue`](/features/next) ایجنٹ گفتگوؤں کو شامل نہیں کرتا، اس لیے یہ آپ کی گفتگو ہی جاری رکھتا ہے۔

## حفاظت اور خاص صورتیں

- کوئی ایجنٹ اپنے ایجنٹس شروع نہیں کر سکتا: ccam اسے `CCAM_AGENT=1` سے نشان زد کرتا ہے، اور وہاں `ccam agent` چلنے سے انکار کر دیتا ہے۔
- `ccam agent` کو روکنے سے (Ctrl+C، کوئی سگنل، یا Claude Code کا کمانڈ کو روک دینا) ایجنٹ بھی رک جاتا ہے۔
- ایجنٹ وہ گفتگو نہیں دیکھتا جس نے اسے بلایا، صرف اپنا کام دیکھتا ہے۔
- جو ایجنٹس ایک ہی وقت میں ایک ہی فائلیں بدلتے ہیں وہ ایک دوسرے کا کام اوور رائٹ کر دیتے ہیں۔ ہر ایک کو کام کا اپنا حصہ، یا اپنا git worktree دیں۔
- جب بلانے والا سیشن کسی دوسرے اکاؤنٹ پر چلا جائے ([`auto_switch`](/features/next#auto-switch))، تو اس کے شروع کیے گئے ایجنٹس بھی اس کے ساتھ رک جاتے ہیں۔ ان کی گفتگوئیں باقی رہتی ہیں: `--resume <id>` انہیں جاری رکھتا ہے۔
- `agent` ایک کمانڈ کا نام ہے، اس لیے کسی نئے اکاؤنٹ کا نام `agent` نہیں رکھا جا سکتا؛ اس نام کا پہلے سے موجود اکاؤنٹ اب بھی `ccam run agent` سے شروع ہوتا ہے۔
