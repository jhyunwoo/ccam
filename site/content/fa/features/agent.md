subagentهای خود Claude Code با حساب نشستی اجرا می‌شوند که آن‌ها را آغاز می‌کند، پس مصرف همان حساب را خرج می‌کنند. `ccam agent "<task>"` یک کار را با `claude -p` در همان پوشه با یکی دیگر از حساب‌های شما اجرا می‌کند و آخرین پاسخ Claude را چاپ می‌کند. وقتی از یک نشست Claude Code فراخوانده شود، مانند یک subagent عمل می‌کند که مصرف حساب دیگری را خرج می‌کند، پس یک کار طولانی می‌تواند از جایی که حساب خود نشست تمام می‌شد فراتر برود و ادامه پیدا کند.

**صندلی‌های Team و Enterprise.** `ccam agent` حساب را خودش انتخاب می‌کند. درون یک سازمان Claude Team یا Enterprise، کار را روی صندلی دیگری اجرا می‌کند، که ممکن است شرایط Anthropic را نقض کند. پیش از آنکه به آن تکیه کنید، [پرسش‌های متداول](/docs/faq#am-i-allowed-to-use-several-claude-code-accounts) را بخوانید و از سازمان خود و Anthropic بپرسید.

## نحوه استفاده

Claude Code آن را با ابزار Bash خود اجرا می‌کند. وقتی [پلاگین ccam](/docs/install#claude-code-plugin) نصب باشد، آن را با زبان ساده بخواهید، برای نمونه «برای بخش‌هایی از این کار از حساب‌های دیگرم استفاده کن»، یا آن را در CLAUDE.md خود بنویسید. مهارت پلاگین به Claude Code می‌گوید هر عامل را در پس‌زمینه آغاز کند، کاری بنویسد که به‌تنهایی قابل فهم باشد، و به عامل‌هایی که فایل‌ها را ویرایش می‌کنند بخش یا git worktree خودشان را بدهد.

```sh
ccam agent "find why TestParse fails and fix it; reply with what you changed"
ccam agent --model opus -- "-v breaks the parser: find out why"
ccam agent --json < task.md            # the task from standard input
ccam agent --resume 7f3c9a2e-… "now add a test for it"
ccam agent --wait=1h "…"               # nobody has room: wait for a reset
ccam --dry-run agent "…"               # the account and command it would run
```

```console
$ ccam agent "summarize what internal/usage does"
ccam: agent runs as work (12% of its 5 hours used); session 7f3c9a2e-5b1d-4c2a-9e8f-1a2b3c4d5e6f
internal/usage looks up the 5-hour and weekly usage of every account …
ccam: agent finished as work; follow up with: ccam agent --resume 7f3c9a2e-5b1d-4c2a-9e8f-1a2b3c4d5e6f "…"
```

آخرین پاسخ Claude به خروجی استاندارد می‌رود؛ خط‌هایی که با `ccam:` آغاز می‌شوند به خطای استاندارد می‌روند. `--json` به جای آن `{account, session_id, result, is_error, accounts}` را چاپ می‌کند، که در آن `accounts` همه حساب‌هایی را فهرست می‌کند که کار با آن‌ها اجرا شد.

کدهای خروج: کد خود claude (`0` وقتی عامل کارش را تمام کرد)، `75` (`EX_TEMPFAIL`) وقتی هیچ حسابی جز حساب فراخواننده ظرفیت ندارد، و `1` برای خطاهای دیگر مانند عاملی که می‌کوشد عامل دیگری را آغاز کند.

## گزینه‌ها

| گزینه | کاری که انجام می‌دهد | پیش‌فرض |
| --- | --- | --- |
| `--model <model>` | مدل عامل؛ پنجره هفتگی آن مدل هم در انتخاب به حساب می‌آید | مدل پیش‌فرض حساب |
| `--resume <id>` | گفتگوی یک عامل قبلی را با یک کار پیگیری ادامه می‌دهد (شناسه نشست در خط نخست و آخر آن آمده است) | خاموش |
| `--json` | حساب، نشست، پاسخ و حساب‌هایی را که کار با آن‌ها اجرا شد چاپ می‌کند | خاموش |
| `--max-usage <1-100>` | حساب‌هایی را که مصرفشان زیر این مقدار است ترجیح می‌دهد | `auto_max_usage`، وگرنه ۱۰۰ |
| `--strategy headroom\|expiring\|balance` | [قاعده انتخاب](/features/next#auto) | `auto_strategy`، وگرنه `headroom` |
| `--cross-org` | با حساب‌های سازمان‌های دیگر هم اجرا می‌کند | `cross_org`، وگرنه خاموش |
| `--wait[=<duration>]` | وقتی هیچ حسابی ظرفیت ندارد، منتظر می‌ماند تا نخستین حساب بازنشانی شود، حداکثر به این مدت | خاموش؛ اگر تنها داده شود `5h` |
| `--dry-run` | فرمان را برای حسابی که انتخاب می‌کرد چاپ می‌کند، بدون آنکه اجرایش کند | خاموش |

## سازوکار

1. **فراخواننده کنار گذاشته می‌شود.** حسابی که `ccam agent` از آن فراخوانده می‌شود (حساب نشستی که ccam آغاز کرده، وگرنه حسابی که این پوشه اجرا می‌کند) هرگز عامل را اجرا نمی‌کند، و پوشه دیگری هم که به همان حساب Claude وارد شده و سقف‌های آن را مشترک دارد آن را اجرا نمی‌کند. عامل در [سازمان](/features/next#auto) فراخواننده می‌ماند، مگر آنکه `--cross-org` چیز دیگری بگوید.
2. **مانند `ccam pick` انتخاب می‌کند.** مصرف به همان شکلی پرسیده می‌شود که [`ccam pick`](/features/pick) می‌پرسد، و عامل‌هایی که با فاصله کمتر از ۲ دقیقه از هم آغاز می‌شوند، تا وقتی به اندازه کافی حساب با ظرفیت وجود داشته باشد، حساب‌های متفاوتی می‌گیرند.
3. **با مجوزهای نشست اجرا می‌شود، هرگز بیشتر.** در `claude -p` کسی نیست که اجازه استفاده از یک ابزار را بدهد، پس عامل حالت مجوز و سطح تلاش نشستی را می‌گیرد که آن را فراخوانده است. وقتی از ترمینال اجرا شود، حالت پیش‌فرض Claude Code و قاعده‌های مجوز تنظیمات شما اعمال می‌شوند. `ccam agent` هیچ گزینه‌ای ندارد که مجوز بیشتری بدهد.
4. **در سقف مصرف، گفتگو ادامه پیدا می‌کند.** وقتی حساب عامل به سقفش می‌رسد، ccam سقف را همان‌طور ثبت می‌کند که [هوک پلاگین](/features/usage#the-limit-record) ثبت می‌کرد و همان گفتگو را با حسابی ادامه می‌دهد که بیشترین ظرفیت را دارد: Claude Code آن را به آنجا کپی می‌کند (`--resume <file> --fork-session`)، با این نخستین پیام: «Your usage limit was reached and ccam moved this conversation to another account. Continue the task you were working on when the limit was reached; do not repeat work that is already complete.» هر حساب فقط یک بار امتحان می‌شود.
5. **هر گفتگوی عامل ثبت می‌شود**، در `~/.local/state/ccam/agent/<session id>.json` (۳۰ روز). `--resume <id>` آن را در پوشه خودش ادامه می‌دهد، با حسابی که آن را اجرا کرده اگر هنوز ظرفیت داشته باشد، وگرنه با حسابی دیگر. [`ccam next --continue`](/features/next) گفتگوهای عامل را کنار می‌گذارد، پس همچنان گفتگوهای خود شما را ادامه می‌دهد.

## ایمنی و موارد خاص

- یک عامل نمی‌تواند عامل‌های خودش را آغاز کند: ccam آن را با `CCAM_AGENT=1` علامت می‌زند، و `ccam agent` از اجرا در آنجا خودداری می‌کند.
- متوقف کردن `ccam agent` (با Ctrl+C، یک سیگنال، یا قطع فرمان از سوی Claude Code) عامل را هم متوقف می‌کند.
- عامل گفتگویی را که آن را فراخوانده نمی‌بیند، فقط کار خودش را.
- عامل‌هایی که هم‌زمان همان فایل‌ها را ویرایش می‌کنند، کار یکدیگر را بازنویسی می‌کنند. به هر کدام بخش خودش از کار، یا git worktree خودش را بدهید.
- وقتی نشست فراخواننده به حساب دیگری می‌رود ([`auto_switch`](/features/next#auto-switch))، عامل‌هایی که آغاز کرده همراه با آن متوقف می‌شوند. گفتگوهایشان می‌مانند: `--resume <id>` آن‌ها را ادامه می‌دهد.
- `agent` نام یک فرمان است، پس هیچ حساب جدیدی نمی‌تواند `agent` نام بگیرد؛ حسابی که از قبل با این نام وجود دارد همچنان با `ccam run agent` آغاز می‌شود.
